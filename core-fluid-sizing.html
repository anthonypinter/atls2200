Fluid Sizing

Media queries change sizes in jumps. Viewport units and the math functions calc(), min(), max() and clamp() let text and spacing change smoothly with the screen, inside limits you set, often with no media query at all.

Using media queries for responsive typography

A heading that suits a laptop can be far too big for a phone, where a long word might not even fit across the screen. The simplest fix is a media query that steps the size up on wide screens:

h1 { font-size: 2rem; }

@media (width >= 1200px) {
  h1 { font-size: 4rem; }
}

That works, but it jumps: at 1199px the heading is 32px, at 1200px it doubles. More breakpoints give smaller jumps, at the cost of more CSS.

Using viewport units for responsive typography

Viewport units grow smoothly: font-size: 6vw is 6% of the window's width, so the heading scales continuously as the window changes. But never size text with vw alone. A size that depends only on the window ignores the reader's settings. A bigger default text size has no effect on it at all, and zooming in makes the window narrower in CSS pixels, so the vw size shrinks by exactly as much as the zoom enlarges it. People who need larger text can't get it.

The fix is to mix in a unit that does respond to zoom, with calc():

h1 {
  font-size: calc(1.5rem + 4vw);
}

Now the heading still grows with the window, and the 1.5rem part grows when someone zooms.

clamp(): grow, within limits

calc(1.5rem + 4vw) still has no limits: on a huge monitor it gets enormous. clamp() adds them. It takes three values, always in this order: a minimum, a preferred value and a maximum.

h1 {
  font-size: clamp(1.75rem, 1rem + 3vw, 3.5rem);
}

The preferred value, 1rem + 3vw, grows as the window widens. clamp() keeps it between 28px and 56px, so the heading is never tiny on a phone or enormous on a big monitor. One line replaces several media queries, and the rem keeps it zoomable.

min(), max() and calc()

min() and max() pick one of their values. width: min(100%, 600px) uses whichever is smaller, so the box fills the screen on phones but never grows past 600px. It works like max-width. max() sets a floor instead: padding: max(10px, 4vw) is never less than 10px. The names feel backwards at first: min() sets an upper limit.

calc() mixes units: calc(100% - 2rem) means "the full width, minus 32px." Inside clamp(), min() and max() you can do math without writing calc().

Watch out

calc(100%-2rem) is silently ignored. The + and - in calc() need a space on each side: calc(100% - 2rem).

Key ideas

  • Media queries change text size in steps; viewport units change it smoothly.
  • Never size text in vw alone: it ignores zoom. Mix in rem: calc(1.5rem + 4vw).
  • clamp(1.75rem, 1rem + 3vw, 3.5rem): grow with the window, but stay between 28px and 56px.
  • min() sets an upper limit (like max-width), max() a lower limit.
  • These work anywhere a length works: font sizes, widths, padding, gap and grid tracks.

Common mistakes

  • Leaving out the spaces: calc(100%-2rem) is ignored.
  • Sizing text in vw alone, so it doesn't grow when people zoom.
  • Putting clamp()'s values in the wrong order. It's always min, preferred, max.
  • Using 100vw for widths on a page with a scrollbar, which causes sideways scrolling. Use 100%.
