Read

Where JavaScript tells you what went wrong

When HTML or CSS has a mistake, you can usually see it: something's in the wrong place or the wrong color. When JavaScript breaks, the page often just stops responding, with no message at all. The explanation is waiting in the browser's console. Open DevTools and click the Console tab.

Errors come in three kinds:

  • A syntax error is a typo in the grammar of the code, like a missing bracket or quote. The browser can't understand the file, so none of the script runs.
  • A runtime error happens while the code is running, like calling something that isn't a function. The script runs up to that line, then stops.
  • A logic error shows no message at all. The code runs fine, but does the wrong thing: the score goes down instead of up.

Every error message tells you what went wrong and where. game.js:21:13 means line 21, character 13. Click it and the browser jumps straight to that line. Read the message slowly: "guess is not defined" tells you that on that line, the name guess doesn't exist. Usually it's misspelled, or declared somewhere else.

Fix the first error first. One error stops the code after it from running, so later problems can't even show up yet. Fix it, reload, and see what's next.

For logic errors, use console.log() to print values as the code runs. Is the number what you expected? Is that line running at all? Each answer narrows down where the bug is hiding.

Tip

Label what you log: console.log("guess:", guess). When there are five values in the console, you'll want to know which is which.

    Key ideas

    • Syntax errors are typos in the grammar of the code: a missing bracket or quote. The whole script won't run.
    • Runtime errors happen while the code runs, such as calling something that isn't a function. Code inside a function only fails when that function is called.
    • Logic errors don't show any message. The code runs but does the wrong thing. Use console.log() to check values as the code runs.
    • Every error message tells you what went wrong and where: game.js:21:13 means line 21, character 13.
    • Fix the first error first. One error often stops the rest of the code from running, so later errors can't appear yet.

    Common mistakes

    • Assuming the error is on the line it names. That's where the code crashed. The real cause can be earlier, such as a selector that matched nothing.
    • Wrong capitalization: addeventListener, queryselector, textcontent. JavaScript is case-sensitive.
    • Using = (assign) when you mean === (compare) inside an if.
    • Forgetting to reload the page after saving, then debugging the old code.
