Table Basics

A table is for data with rows and columns that both mean something: a schedule, a price comparison, a set of results. HTML builds one row at a time, cell by cell.

You'll be able to

  • Decide when a table is the right element, and when it isn't.
  • Build a table from <table>, <tr>, <td> and <th>.
  • Merge cells with colspan and rowspan and keep every row the same width.
  • Style whole columns with <colgroup> and <col>.
Read

What is a table?

A table is a grid of rows and columns. You read it by looking along a row and down a column and finding where they cross: the 10:00 slot on Saturday, the price of the middle plan. Everyone already knows how to read one, which is what makes tables so useful.

Without CSS, an HTML table is hard to read: no borders, no spacing, no stripes. You'll style tables properly in Week 4; this lesson uses a little CSS so you can see the structure.

When should you NOT use tables?

Before CSS layout existed, whole pages were built from tables. Don't do this. Layout tables are hard to change, they bloat the HTML, they don't adapt to small screens, and screen readers announce them as data, which confuses everyone. Use tables for data, and CSS (Flexbox and Grid, Weeks 5 and 6) for layout.

Creating your first table

Three elements make a basic table:

  • <table> wraps the whole thing.
  • <tr> ("table row") holds one row.
  • <td> ("table data") holds one cell. Cells go across, in order, inside their row.
<table>
  <tr><td>Mesa</td><td>6.7</td></tr>
  <tr><td>Royal Arch</td><td>3.4</td></tr>
</table>

There's no element for a column. Columns form because every row has the same number of cells, so the first cell of every row lines up, then the second, and so on. Give one row too few cells and the table has a hole.

Adding headers with <th>

The cells that label a row or a column are headers. Make them <th> ("table header") instead of <td>:

<tr><th>Trail</th><th>Miles</th></tr>
<tr><td>Mesa</td><td>6.7</td></tr>

Browsers show <th> bold and centred, but that's not the point. Headers tell the browser, and screen readers, which cells are labels and which are data. That's how a screen reader can say "Mesa, Miles: 6.7" instead of just "6.7". The next lesson goes deeper.

A <caption> right after <table> gives the table a title.

Allowing cells to span multiple rows and columns

Sometimes a cell needs to stretch. colspan="2" makes a cell two columns wide; rowspan="2" makes it two rows tall.

<tr><th>12:00</th><td colspan="2">Closed for trail work</td></tr>

Spanning cells take up space in other rows, so those rows need fewer cells. With rowspan="2", the row below must leave out one cell, or everything after it shifts one column to the right. Check that every row still adds up.

Providing common styling to columns

Since there's no column element, how do you style a whole column? You could add a class to every cell in it. The cleaner way is <colgroup>, right after the caption, with one <col> for each column:

<colgroup>
  <col>
  <col>
  <col class="today">
</colgroup>

A <col span="2"> covers two columns at once. Only a few CSS properties work on columns: background, border, width and visibility.

    Key ideas

    • Tables are for data with meaningful rows and columns. Never for page layout.
    • <table> holds <tr> rows; rows hold <td> data cells and <th> header cells.
    • Columns exist only because every row has the same number of cells.
    • colspan and rowspan merge cells; the rows they cover need fewer cells.
    • <colgroup> and <col> style whole columns.

    Common mistakes

    • Using a table to lay out a page or a grid of cards.
    • Bold <td>s instead of real <th>s.
    • Rows with different numbers of cells, so columns shift out of line.
    • Adding rowspan but forgetting to remove a cell from the row below.
