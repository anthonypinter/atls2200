Debugging with DevTools

Every browser has developer tools that show exactly which CSS rules apply to an element and which ones lost. This practice version works like the real Elements panel. Use it to fix three bugs on the trail card.

You'll be able to

  • Open DevTools and inspect any element on a page.
  • Read the Styles pane to see which rules apply and which were overridden.
  • Try a fix live in DevTools, then copy it into your real file.
Read

Seeing what the browser sees

When your CSS doesn't do what you expect, guessing and reloading is slow. Every browser comes with DevTools, a set of panels that show exactly what the browser built from your code and why. Right-click anything on a page and choose Inspect.

The Elements panel has two halves. On the left is the element tree: the page as the browser actually built it, which isn't always what you wrote. On the right, the Styles pane lists every rule that matches the selected element, with the winning rules at the top.

Three things in the Styles pane solve most bugs:

  • Crossed-out declarations lost to a stronger or later rule. Look higher in the list to find the winner, then fix the specificity or order.
  • The file name and line number next to each rule tell you exactly where to make the fix.
  • "user agent stylesheet" marks the browser's built-in defaults. You can't edit those, but your own CSS can override them. This is where mystery margins on headings and lists come from.

If a rule you wrote doesn't appear at all, its selector doesn't match, or the stylesheet didn't load. Look for a typo or a broken link.

You can also edit any value right in the Styles pane and see the result immediately. The box model diagram at the bottom shows the element's real margin, border, padding and size.

Watch out

Changes made in DevTools disappear when you reload. Once a fix works, copy it into your real CSS file.

Opening DevTools in your browser

Inspect one elementRight-click it on the page and choose Inspect. DevTools opens with that element selected.
Open DevToolsF12 or Ctrl+Shift+I on Windows. Cmd+Option+I on a Mac. In Safari, turn on "Show features for web developers" in Settings first.
Test on a phone sizeClick the device toolbar icon (a phone and tablet) at the top of DevTools to preview any screen width.

Key ideas

  • The Styles pane lists every rule that matches, with the winning ones at the top.
  • A crossed-out declaration lost to a stronger or later rule. Look above it to find the winner.
  • The file name and line number next to each rule tell you exactly where to fix it.
  • "user agent stylesheet" means the browser's built-in defaults. You can't edit them, but your own CSS can override them.
  • The box model diagram shows an element's real margin, border, padding and size.

Common mistakes

  • Fixing the problem in DevTools and forgetting to copy the fix into the real file.
  • Searching your CSS for a rule that doesn't exist, when it's the browser's default.
  • Not noticing a rule is missing completely, which usually means a typo in the selector or a stylesheet that didn't load.
  • Debugging the wrong element. Check which element is selected in the tree.
