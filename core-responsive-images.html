Responsive Images

CSS can make an image fit any screen, but it can't change which file the browser downloads. HTML can: offer several sizes with srcset and sizes, a different crop with <picture>, and skip images nobody scrolls to with loading="lazy".

You'll be able to

  • Explain the two problems responsive images solve: resolution switching and art direction.
  • Offer several file sizes with srcset and w descriptors, and describe the layout with sizes.
  • Offer sharper copies for high-density screens with x descriptors.
  • Change the crop on small screens with <picture> and <source>, and lazy-load images further down the page.

Why responsive images?

Say your page has a big, wide photo of a trail. On a laptop it looks great. On a phone, two things go wrong:

  • The file is too big. CSS like max-width: 100% shrinks how the image is displayed, but the phone still downloads the full 1600px file, which wastes data and time. Sending a smaller file to smaller screens is called resolution switching.
  • The picture doesn't work small. A wide landscape shrunk to phone size turns the interesting part into a speck. Showing a different crop is called art direction.

For simple graphics like logos and icons, an SVG solves both: it's small and sharp at any size. For photos, HTML gives you srcset, sizes and <picture>.

How do you create responsive images?

Resolution switching: Different sizes

Make several copies of the image at different widths, and list them in srcset. Each entry is a file name and its real width in pixels, written with a w:

<img src="arch-800.jpg"
     srcset="arch-400.jpg 400w, arch-800.jpg 800w, arch-1600.jpg 1600w"
     alt="The sandstone arch at the top of the trail">

The browser works out how many real pixels it needs (including the screen's pixel density) and downloads the smallest file that will look sharp. src stays as the fallback for very old browsers.

Play

Send the right file with srcset

Change how wide the image shows and the screen's pixel density. The browser picks the smallest file that's big enough.

Most phones are 2x or 3x: each CSS pixel uses 2 or 3 real pixels across.

There's a catch. The browser picks the file before your CSS has loaded, so it doesn't know your layout. Unless you say otherwise, it assumes the image fills the whole window. The sizes attribute tells it how wide the image will really be:

<img srcset="mesa-400.jpg 400w, mesa-800.jpg 800w, mesa-1600.jpg 1600w"
     sizes="(width <= 600px) 100vw, 33vw"
     src="mesa-800.jpg" alt="Mesa Trail at sunrise">

Each part of sizes is a media condition and a width (a length or vw, never a percentage). The first condition that matches wins, and the last value, with no condition, is the default. Here: full width on screens up to 600px, a third of the window otherwise.

Resolution switching: Same size, different resolutions

    
Some images always show at the same size, like a 160px-wide logo. They don't need sizes; they just need sharper copies for high-density screens, where each CSS pixel is made of 2 or 3 real pixels. Use x descriptors:

    
<img srcset="logo-160.png, logo-320.png 2x, logo-480.png 3x"
     src="logo-160.png" alt="Trailhead">

    
The first entry has no descriptor, so it counts as 1x. Keep the display size fixed in CSS (width: 160px).

Art direction

    
When a smaller copy isn't enough and you need a different crop, wrap the image in picture. Each <source> has a media condition and a srcset; the browser uses the first one that matches, and falls back to the <img>:

    
<picture>
  <source media="(width < 800px)" srcset="arch-square.jpg">
  <source media="(width >= 800px)" srcset="arch-wide.jpg">
  <img src="arch-wide.jpg" alt="Royal Arch above the trees">
</picture>

    
The <img> is required: it's what actually shows the picture, it holds the alt text, and your CSS targets it. Use media on sources only for art direction; for plain size switching, srcset and sizes let the browser make smarter choices.

Why can't we just do this using CSS or JavaScript?

    
Because they're too late. To show pages quickly, browsers start downloading images as soon as they see an <img> tag, using a preload scanner, before the CSS and JavaScript have even arrived. By the time a script could choose a smaller file, the big one is already downloading. Putting the choices in the HTML lets the browser choose right the first time.

Lazy loading

  


One more HTML attribute saves data on long pages. loading="lazy" waits to download an image until the visitor scrolls near it. On a long gallery, people who never scroll to the bottom never download the images there. This is called lazy loading.

    
Watch out
Don't lazy-load the big image at the top of the page. It's the first thing visitors see, so it should start downloading as early as possible. And keep width and height on lazy images so the page doesn't jump when they arrive.

Implementing your own responsive images

  


For your own projects: export each photo at two or three widths (for example 400, 800 and 1600 pixels), list them in srcset, and add sizes if the image isn't full width. If a photo needs a different crop on phones, make a tighter crop and offer it with <picture>. In CSS, keep img { max-width: 100%; height: auto; }.

Key ideas

      
    
        
  • CSS shrinks how an image is displayed; only HTML can change which file is downloaded.
    • 
        
  • srcset with w descriptors (arch-800.jpg 800w) plus sizes lets the browser pick the smallest sharp file.
    • 
        
  • x descriptors (logo-320.png 2x) suit images that always show at one size.
    • 
        
  • <picture> with <source media> changes the crop (art direction); the <img> inside is required.
    • 
        
  • loading="lazy" on images further down the page, never the first one.
    • 
      

    

    

      
Common mistakes

      
    
        
  • Leaving out sizes with w descriptors, so a small card image downloads at full-window size.
    • 
        
  • Using a percentage in sizes. It takes lengths or vw.
    • 
        
  • Forgetting the <img> inside <picture>. Without it, nothing shows.
    • 
        
  • Uploading a 4000px photo straight from a phone for something shown 400px wide.
