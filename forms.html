    More controls

    datalist, progress and meter

    <datalist>

    Suggestions appear as you type, but people can still enter anything.

    <progress>40%

    Shows how far a task has got. Leave out value for an "in progress, unknown amount" bar.

    <meter>

    A measurement within a known range. low, high and optimum make the browser color it good, okay or bad.

    Sending data

    Where does the data go?

    A form's action says where to send the data and method says how. Each field is sent as name=value, so a field with no name is left out. Fill this in and watch the request it would make. Nothing is actually sent from this page.

    Key ideas
    
      
      
        
    • Every input needs a label. The label's for must match the input's id exactly.
      • 
        
    • The name attribute is what the data is called when the form is sent.
      • 
        
    • Radio buttons in the same group share one name, so only one can be picked. Wrap the group in a <fieldset> with a <legend>.
      • 
        
    • Use <button type="submit"> to send a form and type="button" for anything else.
      • 
      
    
    
    
    
    
      
    Common mistakes
    
      
      
        
    • Using placeholder instead of a label. It disappears when you type and is often low-contrast.
      • 
        
    • Typing type="text" for everything and missing the free validation and keyboards.
      • 
        
    • Reusing the same id twice, so a label points at the wrong input.
      • 
        
    • Forgetting that browser validation doesn't protect a server. Real apps check on the server too.
