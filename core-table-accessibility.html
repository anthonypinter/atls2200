Accessible Tables

A sighted reader finds a cell's meaning by glancing up to its column and across to its row. A screen reader user can't glance. Your markup has to tell their software which headers go with each cell.

You'll be able to

  • Explain how screen reader users move through a table.
  • Connect headers to cells with scope, and with id and headers for complex tables.
  • Add a <caption>, and group rows with <thead>, <tbody> and <tfoot>.
Read

Recap of tables for visually impaired users

Look at any table and you take in its shape at once: what the columns are, where the totals are, which row you care about. A screen reader user hears a table one cell at a time, moving with keyboard shortcuts. Hearing "1,400" on its own is useless: 1,400 what, for which trail?

Screen readers solve this by announcing the matching headers as you move: go across a row and they say the column header; go down a column and they say the row header. But they can only do that if the HTML says which cells are headers.

Using column and row headers

The first step is the one from the last lesson: header cells are <th>, not bold <td>s. Labels at the top of each column are column headers. The first cell of each row is often a label too, like the trail name, and that makes it a row header.

The scope attribute

scope tells assistive technology which direction a header points:

<tr>
  <th scope="col">Trail</th>
  <th scope="col">Miles</th>
</tr>
<tr>
  <th scope="row">Mesa</th>
  <td>6.7</td>
</tr>

scope="col" labels the cells below it; scope="row" labels the cells beside it. For headers that sit over a group of columns or rows, there's scope="colgroup" and scope="rowgroup".

Read

The id and headers attributes

When a table has two levels of headers, scope may not be enough. The precise alternative: give every header an id, then list, on each data cell, the ids of all the headers that apply to it, separated by spaces:

<th id="weekend" colspan="2">Weekend</th>
<th id="sat">Sat</th>
<th id="mesa">Mesa</th>
<td headers="mesa weekend sat">48</td>

It's a lot of typing, and easy to get wrong. Prefer simpler tables where you can: often a complicated table reads better split in two.

Adding a caption with <caption>

  

    
A <caption>, directly after the opening <table> tag, is the table's title. Screen readers announce it when a user enters the table, so they can decide whether to explore it or skip on. Keep it short: "Boulder trail visits by day", not a paragraph.

Adding structure with <thead>, <tbody> and <tfoot>

  

    
Larger tables benefit from grouping their rows:

    
    
      
  • <thead> wraps the header row(s).
    • 
      
  • <tbody> wraps the data. Browsers add one for you if you leave it out.
    • 
      
  • <tfoot> wraps a summary row, like totals.
    • 
    

    
They don't change how the table looks, but they make it easier to style (Week 4), they let browsers repeat the header on every printed page, and they spell out the table's structure for anyone reading your code.

Nesting tables

  

    
You can put a table inside a table cell. Don't, unless there's truly no other way. Screen readers struggle to explain where you are in a table inside a table, and the markup gets hard to follow. Two tables side by side, or one table with a clearer set of columns, nearly always works better.

  


  

    

      
Key ideas

      
    
        
  • Screen reader users hear a table one cell at a time; headers give each cell its meaning.
    • 
        
  • Use <th> for every header, with scope="col" or scope="row".
    • 
        
  • For complex tables, id on headers and headers on data cells link them exactly.
    • 
        
  • A short <caption> lets users decide whether to read the table.
    • 
        
  • <thead>, <tbody> and <tfoot> spell out the structure.
    • 
      

    

    

      
Common mistakes

      
    
        
  • Styling header cells to look like headers without making them <th>.
    • 
        
  • Forgetting the row headers: the first cell of each row is usually a label.
    • 
        
  • A headers attribute that lists an id nobody has, or misspells one.
    • 
        
  • Putting the table's title in a heading or paragraph above it instead of a caption.
    • 
        
  • Nesting tables.
