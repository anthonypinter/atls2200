Debugging isn't scary

Everyone's code breaks, all the time. Debugging, finding and fixing what's wrong, is a normal part of the job, not a sign you've failed. Like any skill, it gets easier once you know your tools. Programming languages that need compiling stop and shout at you when something's wrong. HTML is different, and that makes it both easier and sneakier.

HTML and debugging

There are two kinds of error. A syntax error is a typo in the language itself: a missing closing tag, a missing quote. A logic error is valid code that does the wrong thing: an <h3> where you meant <h2>, a link to the wrong page.

HTML is permissive. When a browser meets a syntax error, it doesn't stop: it guesses what you meant and repairs it, following rules every browser shares. That's why broken pages often look fine. But the repair isn't always what you meant, different repairs can confuse screen readers, and a page that only works by luck will break the moment you add CSS or JavaScript.

Using the DOM inspector

The browser turns your HTML into a tree of elements called the DOM (Document Object Model). The DOM inspector in the browser's DevTools shows that tree: not what you wrote, but what the browser built. Comparing the two shows you exactly where it had to guess.

To open it, right-click anything on a page and choose Inspect. The panel is called Elements in Chrome, Edge and Safari, and Inspector in Firefox.

    HTML validation

    Reading the DOM tree works for small pages. For a whole page, use a validator: a program that checks your HTML against the rules and lists every problem. The standard one is the W3C Markup Validation Service at validator.w3.org. You can give it a URL, upload a file, or paste your code into Validate by Direct Input.

    Interpreting the error messages

    Validator messages are terse, but each gives a line number and points at the code. The common ones:

    • Unclosed element strong: an opening tag with no closing tag.
    • End tag strong violates nesting rules: tags closed in the wrong order.
    • Stray end tag em: a closing tag with nothing open to close.
    • End of file reached when inside an attribute value. Ignoring tag: a missing closing quote.
    • An img element must have an alt attribute.

    Tip

    Fix the first error, then validate again. One missing quote or tag can cause a dozen errors after it, and they all disappear together.

      Key ideas

      • Syntax errors break the language's rules; logic errors are valid code that does the wrong thing.
      • Browsers repair broken HTML instead of stopping, so errors hide.
      • The DOM inspector shows what the browser built, not what you wrote.
      • A validator lists every syntax error, with line numbers.
      • Fix the first error, then validate again.

      Common mistakes

      • Assuming the page is fine because it looks fine.
      • Fixing errors from the bottom of the list up. Later errors are often caused by earlier ones.
      • Editing the DOM inspector and forgetting the change isn't saved to your file.
      • Missing a closing quote, which can swallow a whole tag or link.
