The Cascade

Several rules often try to style the same element. CSS settles every argument the same way, with three ideas: the cascade, specificity and inheritance. Once you know them, "why isn't my CSS working?" usually answers itself.

You'll be able to

  • Explain how source order, specificity and inheritance decide an element's final style.
  • Work out a selector's specificity and predict which rule wins.
  • Control inheritance with inherit, initial, unset and revert.
  • Explain why inline styles and !important make CSS hard to maintain.

Conflicting rules

Cascade

When two rules with equally strong selectors set the same property, the one that comes later wins:

h1 { color: red; }
h1 { color: blue; }  /* headings are blue */

Specificity

But a more specific selector beats a less specific one, wherever it is. A class is more specific than an element name, so this heading is red even though the h1 rule comes later:

.main-heading { color: red; }
h1 { color: blue; }

Inheritance

Some values set on a parent are passed down to its children. Set color: blue on body and every paragraph and span inside turns blue, unless a rule targets them directly.

Understanding how the concepts work together

These three ideas together decide every property of every element. The rest of this lesson takes each in turn.

Understanding inheritance

Inheritance is why you can set a font once and have the whole page use it. Roughly: text properties inherit (color, font-*, line-height, text-align), and box properties don't (border, padding, margin, width, background). That's sensible: if a border on a <section> put a border on every paragraph inside it, nobody would use borders.

Controlling inheritance

Every property also accepts special values that control inheritance:

  • inherit: take the parent's value, even for a property that normally doesn't inherit.
  • initial: use the property's starting value from the CSS specification (for color, that's black).
  • revert: go back to the browser's default style for this element (for a link, blue).
  • unset: act like inherit for properties that inherit, and like initial for the rest.

Understanding the cascade

  


When rules disagree about the same property on the same element, the browser checks three things, in order of importance:

    
    
      
  1. Importance: is a declaration marked !important?
    2. 
      
  2. Specificity: which selector is more specific?
    3. 
      
  3. Source order: which rule comes later?
    4. 
    

    
Source order

    
If importance and specificity tie, later wins. That includes the order of your <link> tags: link a general stylesheet after a specific one, and the general one can win.

    
Specificity

    
The browser scores each selector in three columns:

    
    
      
  • IDs: each #id scores one in the first column.
    • 
      
  • Classes, attributes and pseudo-classes: each .class, [attr] or :hover scores one in the second.
    • 
      
  • Elements and pseudo-elements: each h2 or ::before scores one in the third.
    • 
    

    
Scores are compared column by column, from left to right, so one ID outranks any number of classes, and one class outranks any number of elements. * and combinators score nothing.

Inline styles

    
A style="" attribute beats every selector in every stylesheet. That's one reason to avoid inline styles: the only way to override them is !important.

    
!important

    
Adding !important to a declaration makes it beat every normal declaration, whatever the specificity. It's tempting as a quick fix, but the next time you need to change that property, only another !important will do, and soon nobody can tell which rule wins. Fix the specificity instead.

The effect of CSS location

  


Your stylesheets aren't the only ones. The browser has its default (user-agent) stylesheet, and users can add their own, for example to force larger text. They're layered in this order, each overriding the ones before:

    
    
      
  1. Browser defaults
    2. 
      
  2. User styles
    3. 
      
  3. Your styles (the author)
    4. 
      
  4. Your !important styles
    5. 
      
  5. User !important styles
    6. 
      
  6. Browser !important styles
    7. 
    

    
Notice the flip: for !important, the user beats the author. That's deliberate, so people who need large text or high contrast always get it.

  


  

    

      
Key ideas

      
    
        
  • Later rules beat earlier ones, but only when specificity ties.
    • 
        
  • Specificity: IDs, then classes/attributes/pseudo-classes, then elements. Compare column by column.
    • 
        
  • Text properties inherit; box properties don't.
    • 
        
  • inherit, initial, revert and unset control inheritance for any property.
    • 
        
  • Inline styles beat selectors, and !important beats both. Avoid them.
    • 
      

    

    

      
Common mistakes

      
    
        
  • Fighting specificity with !important instead of a better selector.
    • 
        
  • Expecting a border or padding on a parent to apply to its children.
    • 
        
  • Linking stylesheets in the wrong order, so a general file overrides a specific one.
    • 
        
  • Styling with IDs, which makes later overrides need even stronger selectors.
    • 
        
  • Forgetting that buttons and inputs don't inherit the page's font.
