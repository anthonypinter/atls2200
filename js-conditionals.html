Conditionals

An if statement lets code make decisions. JavaScript checks each condition from top to bottom, runs the first block that is true, and skips everything else.

  • Compare values with === and combine conditions with &&, || and !.
  • Predict which values count as truthy and falsy.
Read

Making decisions

Programs make choices: show the error or don't, say good morning or good evening. A conditional runs code only when something is true.

if (temp >= 85) {
  msg = "Hike early. It'll be hot.";
} else if (temp >= 50) {
  msg = "Perfect hiking weather.";
} else {
  msg = "Bring layers.";
}

JavaScript checks each condition from top to bottom and runs the first block whose condition is true. Then it skips everything else, even if later conditions would also be true. That's why order matters: put the most specific conditions first. If the >= 50 check came first, a 95-degree day would get "perfect hiking weather."

Compare with <, >, <=, >=, and === for "equal." Always use three equals signs. The two-equals version converts types first, so "5" == 5 is true, which hides bugs. "5" === 5 is false. And remember that a single = assigns a value; it never compares.

Combine conditions with && (both must be true), || (at least one must be true) and ! (flips true and false): if (isWeekend && !isRaining).

A condition doesn't have to be a comparison. Any value works. Six values count as false: false, 0, "", null, undefined and NaN. These are called falsy, and everything else is truthy. So if (name) means "if name isn't empty."

Watch out

if (x = 5) doesn't compare. It sets x to 5, and since 5 is truthy, the block always runs.

Key ideas

      
    
        
  • if (condition) { … } else if (other) { … } else { … }. Only the first block whose condition is true runs.
    • 
        
  • Comparisons: === equal, !== not equal, <, >, <=, >=.
    • 
        
  • Use ===, not ==. Triple equals also checks the type, so "5" === 5 is false.
    • 
        
  • Order matters: put the most specific conditions first.
    • 
        
  • Falsy values: false, 0, "", null, undefined, NaN. Everything else is truthy.
    • 
      

    

    

      
Common mistakes

      
    
        
  • if (x = 5): a single = assigns instead of comparing, so the condition is always true.
    • 
        
  • if (day === "Sat" || "Sun"): each side needs its own comparison: day === "Sat" || day === "Sun".
    • 
        
  • Putting temp < 60 before temp < 32. The second can never run.
    • 
        
  • Forgetting break in a switch, so the code falls through into the next case.
    • 
        
  • A semicolon after the condition, as in if (ok); {, makes the block always run.
