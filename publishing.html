Project Structure & Publishing

A tidy folder and sensible file names prevent most "it works on my laptop" bugs. Clean up this messy project, then follow the steps to put a site online with GitHub Pages.

You'll be able to

  • Organize a project folder with index.html at the top and assets in subfolders.
  • Name files so they work on any web server.
  • Publish a site with GitHub Pages and test the live version.
Read

From your laptop to the web

On your own computer, a messy folder mostly works. Once it's on a web server, small sloppiness turns into broken pages. A tidy structure and sensible file names prevent most "it works on my laptop" bugs.

Start with the home page. It must be called index.html and sit at the top of the project folder. When someone visits your site's address without a file name, the server sends index.html automatically. Group everything else by type:

my-site/
  index.html
  about.html
  css/style.css
  images/flatirons.jpg

File names should be lowercase, with hyphens instead of spaces: trail-map.html, not Trail Map.HTML. Most web servers treat Photo.jpg and photo.jpg as different files, even though your laptop may not. That's the most common reason images show up locally and break online.

Link with relative paths like images/flatirons.jpg, never paths to your Desktop or Downloads folder. Those only exist on your computer.

GitHub Pages hosts plain HTML, CSS and JavaScript sites for free. You put your project in a repository, turn on Pages in its settings, and a minute later your site is live at username.github.io/repository-name.

Watch out

Upload the contents of your project folder, not the folder itself. Otherwise index.html ends up one level too deep and the site's address shows a 404.

Publish with GitHub Pages
GitHub Pages hosts plain HTML, CSS and JavaScript sites for free.

  

    
    
      
  1. Make a GitHub accountPick your username carefully. It becomes part of your site's address.

  2. Create a new repositoryClick New, give it a short lowercase name like trail-site, set it to Public, and create it.
    3. 
      
  3. Upload your filesClick "Add file" then "Upload files." Drag in the contents of your project folder so index.html sits at the top level, then click Commit changes.
    4. 
      
  4. Turn on PagesGo to Settings, then Pages. Under "Build and deployment," choose "Deploy from a branch," pick main and / (root), and click Save.
    5. 
      
  5. Wait, then visitIt takes a minute or two. Refresh the Pages settings to see your link. After each change you upload, give it another minute.

        If it doesn't work
        
I get a 404 page
Make sure there's a file named exactly index.html (all lowercase) at the top of the repository, not inside another folder. Then wait a couple of minutes and refresh.

        
The page loads but has no styles or images
Check your paths. Capitalization must match exactly, and paths starting with / point to the wrong place on project sites. Use relative paths like css/style.css.

        
My changes don't show up
Wait a minute after committing, then do a hard refresh (Ctrl+Shift+R, or Cmd+Shift+R on a Mac) so your browser doesn't show an old cached copy.

        
It shows my README instead of my site
GitHub Pages couldn't find index.html, so it fell back to the README. Check the file name and that it's at the top level.

Key ideas

      
    
        
  • The home page is always named index.html. Servers open it automatically.
    • 
        
  • Group files by type: css/, images/, and subfolders for big sections.
    • 
        
  • Keep one project in one folder, and open that folder in your code editor.
    • 
        
  • Test the published site, not just your local copy. Servers are stricter about file names.
    • 
      

    

    

      
Common mistakes

      
    
        
  • Uploading the project folder itself, so the site ends up at /my-project/index.html one level too deep.
    • 
        
  • Image paths that point to your Desktop or Downloads folder.
    • 
        
  • Two copies of a file, like style.css and style (1).css, and editing the wrong one.
    • 
        
  • Making the repository private on a free account, which turns Pages off.
