Fetching Data

Many pages update part of themselves without reloading: new search results, the latest weather, more posts as you scroll. They ask a server for data with fetch(), then use the DOM to show it.

You'll be able to

  • Explain why pages fetch data instead of reloading, and what a promise is.
  • Fetch text and JSON with fetch(), .then() and async/await.
  • Check response.ok and handle errors with .catch() or try...catch.
  • Recognise older XMLHttpRequest code.
Read

What is the problem here?

Traditionally, every click on a link loaded a whole new page from the server, even if only one small part changed. That's slow and wasteful. Instead, JavaScript can request just the data it needs and update part of the page with the DOM. This is sometimes called Ajax, and today it's done with the Fetch API.

Fetching also saves bandwidth: the browser can cache files, and only the new data travels over the network.

The Fetch API

The answer to a request takes time to arrive, from a few milliseconds to several seconds. JavaScript doesn't stop and wait; the code after fetch() keeps running right away. Instead, fetch() returns a promise: a placeholder for a value that will arrive later.

Fetching text content

MDN's first example loads a text file and shows it. You pass a function to the promise's .then() method, and it runs when the response arrives:

fetch(url)
  .then((response) => {
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }
    return response.text();
  })
  .then((text) => {
    poemDisplay.textContent = text;
  })
  .catch((error) => {
    poemDisplay.textContent = `Could not fetch verse: ${error}`;
  });

The first .then() gets a Response object. Reading its body with response.text() takes time too, so it returns another promise, which the second .then() waits for. .catch() runs if anything along the chain fails.

Watch out
A 404 "not found" is a completed request as far as fetch() is concerned, so it won't land in .catch() by itself. Check response.ok and throw an error when it's false. And pages opened by double-clicking the file (file://) can't fetch: use a local server such as VS Code's Live Server, or test on GitHub Pages.

    The XMLHttpRequest API
    
  
    

    Before fetch(), requests were made with XMLHttpRequest (often "XHR"). You'll still find it in older code and tutorials. It does the same job with more ceremony: create the object, attach listeners, then open() and send(). Use fetch() for new code.

    Key ideas
    
      
      
        
    • fetch(url) returns a promise for a Response; the code after it keeps running.
      • 
        
    • Read the body with response.text(), response.json() or response.blob(), each a promise too.
      • 
        
    • A 404 doesn't reject: check response.ok and throw.
      • 
        
    • Handle failures with .catch(), or try...catch inside an async function with await.
      • 
        
    • XMLHttpRequest is the older way; prefer fetch().
      • 
      
    
    
    
    
    
      
    Common mistakes
    
      
      
        
    • Using the data on the line after fetch(), before it has arrived.
      • 
        
    • Forgetting that response.json() needs its own .then() or await.
      • 
        
    • Not checking response.ok, so a 404 page gets parsed as data.
      • 
        
    • Opening the page as file://, where fetch is blocked.
