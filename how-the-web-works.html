How the Web Works

A website is a folder of files on someone else's computer. Your browser asks for those files one at a time and puts the page together. Knowing that explains most "it worked on my laptop" problems.

    Part 3

    Set up your computer

    You don't need a server to start. A text editor and a browser are enough.

    1

    Install a code editor

    VS Code is free and works on every computer. It colors your code and closes tags for you. Don't use Word or TextEdit's rich text mode: they add hidden formatting.

    2

    Make one project folder

    Put every file for the site inside it, with index.html at the top level. Open the whole folder in your editor (File → Open Folder), not single files.

    3

    Open the page in a browser

    Double-click index.html, or drag it into a browser window. Save in the editor, then refresh the browser to see each change.

    4

    Optional: a local server

    The VS Code extension Live Server serves your folder at http://127.0.0.1:5500 and refreshes the page every time you save. It behaves more like the real web than double-clicking.

    Key ideas

    • The browser is the client. The computer holding the files is the server. The browser sends a request, and the server sends back a response with a status code.
    • 200 means OK. 404 means the server has no file at that path. 301 means it moved.
    • Each file is its own request. The HTML arrives first, and the browser finds the rest by reading it.
    • A domain name like github.io is a human-friendly label. DNS looks up the server's numeric address behind it.
    • When a URL ends in a folder (/hikes/), the server sends that folder's index.html.
    • https encrypts the connection. Modern browsers warn visitors about plain http sites.

    Common mistakes

    • Editing a file, forgetting to save, and wondering why the browser hasn't changed.
    • Opening a single file in the editor instead of the project folder, then saving new files in the wrong place.
    • Testing only with file://, then finding broken images online because of capital letters in file names.
    • Thinking the page is one file. If the CSS or an image fails to load, the HTML still shows up without it.
