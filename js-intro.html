The behavior layer

A web page is built in three layers. HTML says what's on the page: a heading, a button, a form. CSS says how it looks. JavaScript says what it does: what happens when someone clicks the button, types in the form, or scrolls to the bottom.

JavaScript is a programming language, and it runs right inside the browser. It can change text and styles after the page has loaded, show and hide things, check a form before it's sent, and fetch new data without reloading the page. Every interactive part of this textbook, from the quizzes to the sidebar, is JavaScript.

Like CSS, JavaScript belongs in its own file, linked from the HTML:

<head>
  <link rel="stylesheet" href="style.css">
  <script defer src="script.js"></script>
</head>

That defer attribute matters. The browser reads your HTML from top to bottom, and without defer, it stops at the script and runs it straight away. A script in the <head> would run before the browser has even reached the <body>, so it can't find the button it's supposed to work with. defer says: download this now, but wait to run it until the whole page has been read.

You'll also see type="module", which waits in the same way. It's what MDN recommends, but it only works when the page is served by a web server, not when you double-click the file to open it.

Tip

JavaScript has nothing to do with Java. The similar name was a marketing decision in 1995, and it has confused people ever since.

    Key ideas
    
      
      
        
    • JavaScript is a programming language that runs in the browser. It can change content, react to clicks and typing, and fetch new data without reloading the page.
      • 
        
    • Put JavaScript in its own file and link it: <script defer src="script.js"></script>. Keeping HTML, CSS and JS in separate files keeps each one easy to read.
      • 
        
    • defer downloads the script while the HTML loads, then runs it once the whole page has been read.
      • 
        
    • type="module" works the same way and is what MDN recommends, but it only runs on a web server (or a local server), not from a file you double-clicked.
      • 
        
    • Comments: // one line or /* several lines */.
      • 
      
    
    
    
    
    
      
    Common mistakes
    
      
      
        
    • A plain <script src> in the head with no defer: the elements don't exist yet, so you get null errors.
      • 
        
    • Inline handlers like <button onclick="go()">. MDN calls this bad practice. Use addEventListener in your JS file instead.
      • 
        
    • Writing <script src="script.js" />. A script tag always needs a closing </script>.
      • 
        
    • A wrong path in src. Nothing happens, and the console shows a 404 for the file.
      •
