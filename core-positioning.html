Positioning

The position property takes an element out of the normal flow and puts it somewhere else: nudged a little, pinned to a corner of its card, stuck to the window, or stuck to the top while you scroll.

You'll be able to

  • Explain what static, relative, absolute, fixed and sticky are each positioned against.
  • Place an element inside a positioning context with position: relative and absolute.
  • Control which overlapping element is on top with z-index.
  • Build sticky headers, stacked tab panels and a sliding panel.

Introducing positioning

Normally every element sits where the normal flow puts it, one after another. The position property lets you move an element from there, for things that normal flow, Flexbox and Grid can't do: a badge over the corner of a photo, a header that stays at the top of the window, a menu that slides in over the page.

Once an element is positioned, the offset properties top, right, bottom and left move it. The question each position value answers is: measured from where? Try them all first, then we'll go through each one.

Static positioning

position: static is the default. The element sits in the normal flow, and top, left and z-index have no effect. You'll rarely write it, except to undo another position value.

Read

Relative positioning

position: relative keeps the element in the normal flow, then lets you nudge it from there. Its original space stays reserved, so nothing around it moves; the element can end up overlapping its neighbours.

Introducing top, bottom, left, and right

The offsets can feel backwards. top: 30px pushes the element 30px away from its top edge, so it moves down. left: 30px moves it right. To move up or left, use bottom and right, or a negative value.

.positioned {
  position: relative;
  top: 30px;    /* 30px down */
  left: 30px;   /* 30px right */
}

On its own, relative positioning is mostly used for small nudges. Its big job is the next one: being the reference point for absolutely positioned children.

Absolute positioning

Setting position: absolute

position: absolute takes the element out of the normal flow completely. It no longer takes up space: the elements after it close up as if it weren't there. It still has its own margins, but they don't collapse with anything.

Positioning contexts

An absolute element's offsets are measured from its containing block: the nearest ancestor that is itself positioned (anything but static). If there isn't one, it's the initial containing block, roughly the size of the window at the top of the page.

That's why you'll see this pattern everywhere. To pin a badge to a card's corner, make the card the positioning context:

.card { position: relative; }   /* the context */
.card .badge {
  position: absolute;
  top: 8px;
  right: 8px;
}

Without position: relative on the card, the badge looks for the next positioned ancestor up the page and often ends up in the corner of the whole page.

Introducing z-index

Positioned elements can overlap. By default, the one that comes later in the HTML is drawn on top. z-index changes that: higher numbers come forward. It takes whole numbers with no unit, including negatives; the default, auto, acts like 0.

z-index only works on positioned elements (and on flex and grid items). On a static element it does nothing.

Fixed positioning

position: fixed works like absolute, but it's positioned against the viewport (the browser window), not an ancestor. It stays in the same place on screen while the page scrolls under it. That's how headers, chat buttons and cookie banners stay visible.

.site-header {
  position: fixed;
  top: 0;
  width: 100%;
}
main { margin-top: 60px; }   /* so the header doesn't cover the start of the page */

Because a fixed element is out of the flow, the content underneath doesn't know it's there. Leave room for it, or it will cover the top of your page.

Sticky positioning

Basic example

position: sticky is a mix of relative and fixed. The element scrolls with the page normally until it reaches its offset, then it sticks there, until its parent scrolls out of view and takes it away.

.positioned {
  position: sticky;
  top: 30px;   /* stick when 30px from the top */
}

Sticky needs an offset like top; without one it never sticks.

Scrolling index

A classic use is an alphabetical list where each letter heading sticks at the top until the next letter pushes it away. Each heading only sticks inside its own section. Sticky also works inside any scrolling box, not just the page: the element sticks to the nearest ancestor that scrolls.

Practical positioning examples

A tabbed info-box

A tabbed box shows one panel at a time. A neat way to build it: give the panels' wrapper position: relative, and stack every panel inside it with position: absolute; top: 0; left: 0. They all occupy the same spot, and a small script hides all but the selected one (with a class like .is-hidden { display: none; }) and sets aria-selected on the tabs.

A fixed position tabbed info-box

Change the box to position: fixed; top: 0 and it stays on screen while the rest of the page scrolls past. The page content then needs a margin on that side (for example margin-left as wide as the box) so it isn't hidden underneath.

A sliding hidden panel

A panel can wait just off-screen and slide in when you need it. Give it position: fixed and a negative right equal to its width, so it's hidden past the edge of the window. A class like .open { right: 0; } brings it back, and a transition on right animates the move. The button that opens it is positioned too, with a z-index so it stays above the panel.

Key ideas

  • static is the default: offsets and z-index do nothing.
  • relative nudges the element; its original space stays reserved. top: 30px moves it down.
  • absolute leaves the flow and is placed inside the nearest positioned ancestor, so put position: relative on the parent.
  • fixed is placed against the viewport; sticky scrolls normally, then sticks at its offset inside its parent.
  • z-index brings positioned elements forward; with equal values, later in the source is on top.

Common mistakes

  • Using absolute without a positioned parent, so the element flies to the corner of the page.
  • Building whole layouts with absolute positioning. Use Flexbox or Grid, and save positioning for overlays and badges.
  • Setting z-index on a static element.
  • Sticky that never sticks because there's no top value, or a parent has overflow: hidden.
