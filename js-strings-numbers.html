When + adds, and when it joins

Numbers work the way you'd expect: +, -, * and /, with parentheses to control the order. Two extra operators are handy. % gives the remainder after dividing, so 7 % 2 is 1, and ** raises to a power.

The trouble starts with +, because it does two jobs. With two numbers, it adds. If either side is a string, it joins them instead, which is called concatenation:

5 + 5       // 10
"5" + 5     // "55"
"5" * 2     // 10, because * always tries to make numbers

This matters because anything a visitor types into a form arrives as a string. Add 5 to an input's value of "10" and you get "105". Convert it first with Number(input.value). If the text isn't a number, you get NaN, short for "not a number."

To build a sentence from values, a template literal is easier than joining pieces. Use backticks instead of quotes, and put any value inside ${ }:

const miles = 6.7;
const msg = `Mesa Trail is ${miles} miles long.`;

Strings come with built-in methods: .toUpperCase(), .includes("Mesa"), .trim() and many more. Methods return a new string; the original never changes. .length is a property, not a method, so it has no parentheses.

Tip

(0.1 + 0.2) gives 0.30000000000000004. Computers store decimals approximately. When showing money or distances, round for display with .toFixed(2).

Key ideas

  • Arithmetic: + - * /, % (remainder) and ** (power). Use parentheses to control the order.
  • If either side of + is a string, it joins instead of adding. The other operators always try to convert to numbers.
  • Convert text to a number with Number("12"), and a number to text with String(12) or .toFixed(2).
  • Shortcuts: score += 10, count++, count--.
  • Template literals use backticks: `Hi ${name}`. They can also span several lines.
  • .length is a property (no parentheses). .toUpperCase() is a method (with parentheses).

Common mistakes

  • Adding form values without converting them: "2" + "3" is "23".
  • Using normal quotes for a template: "Hi ${name}" prints the ${name} literally. It needs backticks.
  • Expecting a method to change the original: text.trim(); on its own does nothing useful. Save the result: text = text.trim();
  • Off-by-one indexes: the first character is [0], and the last is [text.length - 1].
  • Expecting 0.1 + 0.2 to be exactly 0.3. Round for display with .toFixed().
