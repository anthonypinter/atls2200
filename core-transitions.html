Transitions

By default a style change is instant: hover a button and its colour snaps. A transition tells the browser to blend from the old value to the new one over time, so the change feels smooth instead of abrupt.

You'll be able to

  • Write transitions with transition and its four longhand properties.
  • Know which properties can be transitioned, and which animate smoothly.
  • Transition several properties, a menu, and even display.
  • Respect visitors who ask for reduced motion, and react to transition events in JavaScript.

Which CSS properties can be transitioned?

A transition works by calculating the in-between values, so the property needs values that have an in-between: colours, lengths, numbers, transforms, opacity. Properties with on/off values, like display or font-family, just switch. And auto can't be transitioned: height: 0 to height: auto jumps.

Defining transitions

The transition shorthand takes the property, the duration, a timing function and a delay:

.btn {
  background: #0b6b5e;
  transition: background-color 200ms ease, transform 200ms ease;
}
.btn:hover {
  background: #084c43;
  transform: translateY(-2px);
}
  • transition-property: which properties to animate. Name them, rather than all, so nothing unexpected moves.
  • transition-duration: how long, in s or ms. About 150 to 400ms feels right for interface changes.
  • transition-timing-function: the speed curve, like ease, linear, ease-out.
  • transition-delay: how long to wait before starting.

Put the transition on the element's normal state, not on :hover, so it animates on the way in and the way out.

Examples

Multiple animated properties

List several transitions with commas: transition: width 2s, height 2s, background-color 2s, rotate 2s;.

When property value lists are of different lengths

With the longhands, the lists are matched up by position. If transition-duration has fewer values than transition-property, its values repeat to fill the gap; extra values are ignored.

transition-property: opacity, left, top, height;
transition-duration: 3s, 5s;   /* = 3s, 5s, 3s, 5s */

Using transitions when highlighting menus

A short transition on menu links, transition: background-color 0.3s ease-out, color 0.3s ease-out;, makes hover and focus states feel smooth.

Transitioning display

Normally an element switching from display: none to display: block can't fade in: it doesn't exist until the switch. Two newer features fix that. allow-discrete lets display take part in the transition, and @starting-style says what the element looks like the moment it appears, so it has something to transition from:

.panel {
  opacity: 0;
  display: none;
  transition: opacity 0.6s, display 0.6s allow-discrete;
}
.panel.showing {
  opacity: 1;
  display: block;
}
@starting-style {
  .panel.showing { opacity: 0; }
}

Keyframe animations and reduced motion

A transition needs a trigger, like a hover or a class change. An animation runs by itself, through steps you describe with @keyframes:

@keyframes pulse {
  from { transform: scale(1); }
  to   { transform: scale(1.08); }
}
.new-badge {
  animation: pulse 800ms ease-in-out infinite alternate;
}

Some people get dizzy or sick from motion on screen, and set their device to reduce it. Wrap big or looping motion in @media (prefers-reduced-motion: no-preference) { … }, so it only runs for people who haven't asked for less.

JavaScript examples

Using transitions to make JavaScript functionality smooth

When JavaScript changes a style, a transition in the CSS animates it, with no animation code in your script. Set transition: transform 1s on a ball, and every time JavaScript sets a new transform, the ball glides there.

Detecting the start and completion of a transition

Transitions fire events you can listen for: transitionrun (it's set up), transitionstart (after any delay), and transitionend (finished). Each tells you the propertyName and the elapsedTime.

Key ideas

  • Transitions blend between two states; animations run through keyframes on their own.
  • Only properties with in-between values animate; auto and display normally snap.
  • Put transition on the normal state, name the properties, and keep it to 150–400ms.
  • transform and opacity animate most smoothly.
  • Respect prefers-reduced-motion.

Common mistakes

  • transition only on :hover, so it snaps back.
  • transition: all, which animates things you didn't mean to.
  • Trying to transition height to auto.
  • Slow, bouncy motion on every interaction.
  • Looping animations with no reduced-motion fallback.
