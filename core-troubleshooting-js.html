Troubleshooting JavaScript

Everyone's code breaks. The skill is finding out why, quickly: reading the console's error messages, logging values, using the debugger, and writing code that handles bad input without crashing.

You'll be able to

  • Tell syntax, runtime and logic errors apart.
  • Read an error message and its line number, and fix the first error first.
  • Inspect values with console.log(), console.error() and the debugger.
  • Handle errors in your own code with checks, throw and try...catch.
Read

Types of error

When HTML or CSS has a mistake, you can usually see it. When JavaScript breaks, the page often just stops responding, with no message at all. The explanation is waiting in the browser's console: open DevTools and click the Console tab.

Errors come in three kinds:

  • A syntax error is a typo in the grammar of the code, like a missing bracket or quote. The browser can't understand the file, so none of the script runs.
  • A runtime error happens while the code is running, like calling something that isn't a function. The script runs up to that line, then stops.
  • A logic error shows no message at all. The code runs fine but does the wrong thing: the score goes down instead of up.

Fixing errors reported in the console

MDN's example is the number guessing game from What is JavaScript?, with bugs added. Every error message tells you what went wrong and where. game.js:21:13 means line 21, character 13; click it and the browser jumps straight to that line.

Read the message slowly. guessSubmit.addeventListener is not a function means that on that line, the thing you called isn't a function. Here it's a capital-letter typo: JavaScript is case-sensitive, so it's addEventListener. lowOrHi is null means a querySelector() found nothing, usually because the selector is wrong (a class without its dot).

Fix the first error first. One error stops the code after it from running, so later problems can't even show up yet. Fix it, reload, and see what's next.

A logic error

MDN's game also has a bug with no message: the "random" number is always 1. To find a logic error, use console.log() to print values as the code runs. Is the number what you expected? Is that line running at all? Each answer narrows down where the bug is hiding.

    Other common errors

    A handful of mistakes cause most errors:

    • = (assign) where you meant === (compare): if (guessCount = 10) sets the count to 10 instead of checking it, so the game ends after one guess.
    • A missing ), } or quote: "missing ) after argument list", "missing } after function body", "unterminated string literal".
    • A misspelled name: "something is not defined".

    Common JavaScript problems

    Beyond typos, a few problems trip up everyone at some point: using a variable outside the block or function where it was created (scope), confusing let and var, and code that runs before the data it needs has arrived (like using the result of fetch() before it's finished). You'll meet each of these in later lessons.

    The Console API

    console.log() is one of several console methods. console.error() prints in red, and shows the call stack: the chain of function calls that led to that line, most recent first. That tells you not just where something happened, but how the code got there.

    The second call logs an error, then crashes. The log right before the crash, trail: undefined, shows why: the lookup found nothing. In the browser's own console, the red error also lists the call stack: getTrail, called from showMiles, called from the top of the script.

    Using the JavaScript debugger

    For trickier bugs, the debugger lets you pause the code and look around. In the Sources tab (Chrome) or Debugger tab (Firefox), click a line number to set a breakpoint. When the code reaches that line, it pauses. The Scope panel shows every variable's current value, the Call Stack panel shows how you got there, and the step buttons run one line at a time.

    You can also pause from your code by writing debugger; on a line. It does nothing unless DevTools is open.

    Finding help

    When you're stuck, search for the exact error message. MDN's JavaScript error reference explains every message; Stack Overflow probably has someone who hit the same problem; and caniuse.com tells you which browsers support a feature. When you ask a person, include the code, the full error and what you've already tried.

    Key ideas

    • Syntax errors stop the whole script; runtime errors stop it at that line; logic errors give no message.
    • Every error says what and where: game.js:21:13 is line 21, character 13. Fix the first error first.
    • console.log() checks values; console.error() also shows the call stack; breakpoints pause the code.
    • Check input with typeof and Number.isNaN(); throw new Error() stops with a clear message.
    • try...catch handles a thrown error so the rest of the script keeps running.

    Common mistakes

    • Assuming the error is on the line it names. The real cause can be earlier, such as a selector that matched nothing.
    • Wrong capitalization: addeventListener, queryselector. JavaScript is case-sensitive.
    • Using = when you mean === inside an if.
    • Forgetting to reload the page after saving, then debugging the old code.
