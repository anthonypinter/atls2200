Sizing

Every box has a size, whether it comes from its content or from you. Knowing which, and choosing values that adapt instead of fixed numbers, is the difference between a layout that works on every screen and one that only works on yours.

You'll be able to

  • Explain the difference between a box's intrinsic size and a size you set.
  • Size boxes with percentages, and predict what percentage margins and padding resolve against.
  • Use min-height, max-width and max-width: 100% on images so content can adapt.
  • Size things relative to the browser window with vw and vh.

The natural or intrinsic size of things

HTML elements have a natural size before any CSS touches them. An image is as big as the file's pixel dimensions. A paragraph is as tall as its lines of text. This is its intrinsic size: it comes from the content.

An empty <div> has no content, so it has no height at all. Give it a border and you just see a flat line, the top and bottom borders touching. Put some text inside and it grows to fit.

Setting a specific size

You can override the intrinsic size with width and height. That's an extrinsic size: it comes from outside the content. A box with height: 120px stays 120px tall whatever is inside, and if the text needs more room it overflows. (The next lesson, Overflow, covers what to do about that.)

Using percentages

A percentage width is a share of the containing block, usually the parent. width: 50% is half of whatever contains it, so the box grows and shrinks with its parent. That's much safer than a fixed width like width: 1000px, which sticks out on a 390px phone and makes the whole page scroll sideways.

The pattern you'll use constantly combines a percentage with a limit:

.content {
  width: 100%;
  max-width: 600px;
}

On a phone the box fills the screen. On a big screen it stops at 600px, which keeps lines of text short enough to read. Percentage heights are trickier: they only work if the parent has a set height, which it usually doesn't.

Percentage margins and padding

Here's a surprise: percentage margin and padding are calculated from the containing block's width, even on the top and bottom. So padding: 10% gives the same amount of space on all four sides, and that space changes when the parent gets wider, not taller.

.box {
  margin: 10%;    /* 10% of the parent's width, on every side */
  padding: 10%;
}

min- and max- sizes

Instead of a fixed size, you can set a floor or a ceiling and let the content decide the rest. Text wraps onto more lines as the screen narrows, so a box with a fixed height eventually can't hold it. min-height says "at least this tall", and the box still grows when the content needs it.

max-width works the other way: the box can be narrower but never wider. min-width sets a floor for width.

max-width on images

An image is drawn at its intrinsic size, so a 1200px photo in a 400px column sticks out. You could set width: 100%, but that also stretches small images past their natural size, and they go blurry. The standard fix is:

img {
  max-width: 100%;
  height: auto;   /* keep the shape when it shrinks */
}

Now big images shrink to fit their container, and small ones stay at their natural size.

Viewport units

The viewport is the visible part of the page in the browser window. Viewport units size things relative to it, not to the parent:

  • 1vw is 1% of the viewport's width.
  • 1vh is 1% of the viewport's height.

So min-height: 100vh makes a banner that fills the screen, and width: 50vw is half the window wide whatever its parent is. On phones, where browser toolbars appear and disappear, 100dvh adjusts for them.

A related tool is aspect-ratio. Set a width and aspect-ratio: 16 / 9, and the browser works out the height, which is perfect for video and image placeholders.

Key ideas

  • Without a set size, a box takes its intrinsic size from its content. An empty block has no height.
  • Percentage widths are a share of the containing block. width: 100%; max-width: 600px fills phones and caps big screens.
  • Percentage margins and padding use the containing block's width, even on the top and bottom.
  • Prefer min-height to height for boxes with text, and max-width: 100% for images.
  • vw and vh are 1% of the viewport's width and height.

Common mistakes

  • Big fixed widths like width: 1000px that overflow on phones.
  • A percentage height that does nothing because the parent has no set height.
  • Expecting padding-top: 10% to be 10% of the parent's height.
  • Using width: 100% on images, which stretches small ones until they blur.
