JavaScript in the Browser · Events

Events

Events are signals the browser sends when something happens: a click, a key press, a form being submitted. You listen for them with addEventListener and run a function in response.

    Key ideas
    
      
      
        
    • el.addEventListener("click", handler): the event type as a string, then the function to run. Pass the function itself, without ().
      • 
        
    • The handler receives an event object, usually named e or event. e.target is the element the event happened on.
      • 
        
    • e.preventDefault() stops the browser's default action: a form reloading the page, or a link navigating.
      • 
        
    • Useful types: click, input (every change to a field), change, submit, keydown, focus, blur, mouseover, mouseout.
      • 
        
    • Events bubble from the target up through its ancestors. Delegation uses this: one listener on a parent handles all its children, even ones added later.
      • 
        
    • Remove a listener with removeEventListener, passing the same named function.
      • 
      
    
    
    
    
    
      
    Common mistakes
    
      
      
        
    • addEventListener("click", go()) runs go immediately. Pass go.
      • 
        
    • "onclick" as the event name. The type is just "click".
      • 
        
    • Inline HTML handlers like onclick="…". MDN says never to use them: they mix languages and are often blocked by security settings.
      • 
        
    • Listening for click on a form's submit button instead of submit on the form, which misses submissions made by pressing Enter.
      • 
        
    • Forgetting preventDefault(), so the page reloads and your changes vanish.
