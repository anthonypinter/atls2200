Events

Most JavaScript on a page waits for something to happen: a click, a key press, a form being submitted. Events are how your code finds out, so it can respond.

You'll be able to

  • Listen for events with addEventListener(), and remove listeners again.
  • Read the event object: target, key and more.
  • Stop a default action, like a form reloading the page, with preventDefault().
  • Explain bubbling and capture, and use event delegation with target and currentTarget.
Read

What is an event?

An event is a signal the browser sends when something happens: the user clicks, presses a key, submits a form or resizes the window; a video finishes; a page finishes loading. Your code can respond by attaching an event listener (a function that runs when the event fires, also called an event handler).

Using addEventListener()

Give addEventListener() the event's name as a string, then the function to run. MDN's example changes the page's background color every time a button is clicked:

const btn = document.querySelector("button");

function random(number) {
  return Math.floor(Math.random() * (number + 1));
}

btn.addEventListener("click", () => {
  const rndCol = `rgb(${random(255)} ${random(255)} ${random(255)})`;
  document.body.style.backgroundColor = rndCol;
});

Listening for other events

There are many events. Some useful ones: click and dblclick; focus and blur when a field gains or loses focus; input on every change to a field; keydown; mouseover and mouseout; and submit on a form. Not every element fires every event: submit only comes from forms.

    Removing listeners
    
    
    removeEventListener() takes the same event name and the same function you added. That's one reason to use named functions for listeners you'll remove later: an anonymous function can't be named again.
    
    
    Adding multiple listeners
    
    
    You can add several listeners for the same event on the same element. They all run, in the order you added them.

    Other event listener mechanisms
    
  
    

    Event handler properties
    
    
    Elements also have properties like onclick you can set to a function: btn.onclick = bgChange;. It works, but each property holds only one function, so a second assignment replaces the first.
    
    
    Inline event handlers: don't use these
    
    
    Old code sometimes puts JavaScript straight into HTML: <button onclick="bgChange()">. It mixes JavaScript into your markup, is hard to maintain, and is blocked by many sites' security settings. Keep your JavaScript in your script with addEventListener().

    Event objects
    
  
    

    The browser passes your listener an event object, usually named e, evt or event. event.target is the element the event happened on, so one function can handle events from many elements.
    
    
    Extra properties of event objects
    
    
    Different events carry different information. A keydown event's key property tells you which key was pressed:
    
    
    textBox.addEventListener("keydown", (event) => {
  output.textContent = `You pressed "${event.key}".`;
});

    Preventing default behavior
    
  
    

    Some events come with a default action. Submitting a form sends it and reloads the page; clicking a link navigates away. preventDefault() stops that, so your code can handle it instead, for example to check the fields first:
    
    
    form.addEventListener("submit", (e) => {
  if (fname.value === "" || lname.value === "") {
    e.preventDefault();
    para.textContent = "You need to fill in both names!";
  }
});
    
    
    Watch out
    Listen for submit on the form, not click on its button. Pressing Enter in a field submits the form without clicking anything.

    Event bubbling
    
  
    

    Events travel. A click on a button inside a <div> fires on the button first, then on the div, then on <body>, all the way up to the document. This is event bubbling: the event bubbles up from the innermost element.
    
    
    Stopping propagation
    
    
    Calling event.stopPropagation() in a listener stops the event going any further up. MDN's example is a video inside a box: clicking the video plays it, but without stopPropagation() the click also reaches the box, whose listener hides it.
    
    
    Event capture
    
    
    There's also an earlier capture phase, which goes the other way: from the outside in. Listeners only run during it if you ask, with addEventListener("click", handler, { capture: true }). You'll rarely need it.

    Event delegation
    
  
    

    Bubbling makes a powerful trick possible. Instead of adding a listener to each of 50 items, add one to their container and check event.target to see which item was clicked. That's event delegation, and it even works for items added later.
    
    
    target and currentTarget
    
    
    event.target is the element the event started on (the innermost one). event.currentTarget is the element whose listener is running now: in delegation, that's the container.

    Key ideas
    
      
      
        
    • el.addEventListener("click", fn) runs fn every time the event fires. removeEventListener() needs the same function.
      • 
        
    • Pass the function itself: fn, not fn().
      • 
        
    • The event object tells you what happened: e.target, e.key and more.
      • 
        
    • e.preventDefault() stops a default action like a form submit.
      • 
        
    • Events bubble up through ancestors; stopPropagation() stops them. Delegation puts one listener on a container.
      • 
      
    
    
    
    
    
      
    Common mistakes
    
      
      
        
    • addEventListener("click", go()): runs go once, immediately.
      • 
        
    • Listening for click on a submit button instead of submit on the form.
      • 
        
    • Inline onclick="…" attributes in HTML.
      • 
        
    • Using e.target in delegation without checking it's the kind of element you expect.
