Fetching Data

fetch() asks a server for data, usually JSON, and lets you update part of the page without reloading it. The answer takes time to arrive, so your code has to wait for it and be ready for things to go wrong.

    Key ideas
    
      
      
        
    • fetch(url) returns a promise: a placeholder for a value that will arrive later. .then() runs when it does, and .catch() runs if something fails.
      • 
        
    • async/await is another way to write the same thing. await pauses that function until the promise settles, and try/catch handles errors.
      • 
        
    • Code after fetch() keeps running right away. It doesn't wait for the response.
      • 
        
    • A 404 is not an error to fetch. Check response.ok yourself and throw if it's false.
      • 
        
    • response.json() reads the body and parses it as JSON (it also returns a promise).
      • 
        
    • Pages opened as file:// can't fetch. Use a local server, such as VS Code's Live Server, or test on GitHub Pages.
      • 
      
    
    
    
    
    
      
    Common mistakes
    
      
      
        
    • Using the data on the line after fetch(). It isn't there yet. Use it inside .then() or after await.
      • 
        
    • Forgetting return before response.json() in a .then(), so the next .then() gets undefined.
      • 
        
    • Skipping the response.ok check, then trying to parse a 404 error page as JSON.
      • 
        
    • Using await outside an async function (only allowed at the top level of a module).
      • 
        
    • Opening the HTML file directly and wondering why every request fails with Failed to fetch.
