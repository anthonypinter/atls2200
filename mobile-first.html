Start small, then add

There are two ways to make a site responsive. You can design for a laptop and then squeeze it onto a phone, undoing styles as the screen shrinks. Or you can start with the phone and add to it as the screen grows. The second way is called mobile first, and it almost always means less CSS and fewer bugs.

The reason is that the phone layout is usually the simplest: one column, everything stacked, full width. That's close to what HTML does with no CSS at all. So your base styles, outside any media query, describe the phone version. Then each min-width media query adds only what changes on wider screens:

/* Phone: everything stacks */
.page { padding: 16px; }

/* Tablet and up: two columns */
@media (min-width: 700px) {
  .page {
    display: grid;
    grid-template-columns: 2fr 1fr;
    gap: 24px;
  }
}

Working this way, you never write a rule just to undo another one. And because the phone version is built first, it gets your full attention instead of being an afterthought.

Mobile first also applies to content. If something is too much for a phone, ask whether it's needed at all, rather than hiding it on small screens. Phone visitors often want exactly the same information as everyone else.

Tip

Narrowing your browser window is a good first check, but test on a real phone too. Touch targets, real font sizes and the on-screen keyboard only show up on the real thing. DevTools' device mode is a good middle step.

    Key ideas

    • The phone layout is usually the simplest: one column. Starting there means less CSS to undo later.
    • Styles outside any media query apply everywhere. Media queries only add changes for wider screens.
    • Use min-width queries, listed from smallest to largest.
    • Add a breakpoint when the layout starts to look wrong as you widen the window, not at a specific device's width.

    Common mistakes

    • Designing for a laptop, then cramming it onto a phone with lots of max-width overrides.
    • Only testing by shrinking the browser window. Check on a real phone too.
    • Fixed widths like width: 960px on a wrapper, which cause sideways scrolling on phones.
    • Hiding important content on mobile instead of rearranging it.
