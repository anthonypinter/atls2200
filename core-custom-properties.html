CSS Custom Properties

Type a colour forty times and changing it means forty edits. A custom property (often called a CSS variable) stores a value once, under a name, so every rule that uses it updates together.

You'll be able to

  • Declare custom properties with --name and use them with var().
  • Define global values on :root, and override them for one part of the page.
  • Give var() a fallback, and explain what happens with an invalid value.
  • Register a typed property with @property, and read or set values from JavaScript.

Declaring custom properties

Using a prefix of two dashes (--)

A CSS variable is a property whose name starts with two dashes. You declare it in a rule, like any other property:

section {
  --main-bg-color: brown;
}

Names are case-sensitive: --Brand and --brand are different.

Using the @property at-rule

For more control, @property registers a custom property with a type, whether it inherits, and a starting value. More on that below.

Referencing custom properties with var()

To use the value, put its name in var(): background-color: var(--main-bg-color);. Writing color: --brand; does nothing: you always need var().

First steps, and the :root pseudo-class

The usual pattern is to declare site-wide values once, on :root (the <html> element), so every element can use them:

:root {
  --brand: #0b6b5e;
  --space: 16px;
}
.btn {
  background: var(--brand);
  padding: var(--space);
}

Change --brand in one place and every button, link and heading that uses it follows. The same trick gives you a dark theme: redefine just the colour variables inside @media (prefers-color-scheme: dark).

Inheritance of custom properties

Custom properties inherit, like color. An element sees the value set on itself or on its nearest ancestor. That's what makes overrides work: set --brand on one .card, and that card and everything inside it use the new value, while the rest of the page doesn't change.

Using @property to control inheritance

A registered property can switch inheritance off. Then only the element it's set on gets the value; its children get the initial-value:

@property --box-color {
  syntax: "<color>";
  inherits: false;
  initial-value: #9aa2bf;
}

Custom property fallback values

Defining fallbacks in the var() function

Add a second value to var(), after a comma, to use when the variable isn't defined: var(--sale, crimson). Fallbacks can nest: var(--my-var, var(--my-background, pink)).

Fallbacks using the @property initial value

A registered property also falls back to its initial-value when it's given a value of the wrong type, like peenk for a <color>.

Invalid custom properties

Normally an invalid declaration is simply skipped. Variables are different: the browser can't know whether var(--text-color) makes sense until it substitutes the value. So with :root { --text-color: 16px; }, the rule p { color: var(--text-color); } isn't skipped. It becomes invalid when used, and color falls back to its inherited value, not to your previous rule. (Registering the property with a <color> syntax prevents that.)

    Values in JavaScript

    JavaScript (Week 7) can read and change custom properties, which is how interactive themes work. Changing one variable restyles everything that uses it:

    // read
getComputedStyle(element).getPropertyValue("--brand");
// set
element.style.setProperty("--brand", "#b4410c");

    Key ideas
    
      
      
        
    • Custom properties start with -- and are read with var().
      • 
        
    • Declare global values on :root; override them on any element for that part of the page.
      • 
        
    • They inherit, unless registered with @property and inherits: false.
      • 
        
    • var(--x, fallback) covers an undefined variable.
      • 
        
    • A wrong-type value isn't skipped: the property falls back to inherited or initial.
      • 
      
    
    
    
    
    
      
    Common mistakes
    
      
      
        
    • color: --brand; without var().
      • 
        
    • Mismatched case: --Brand versus --brand.
      • 
        
    • Declaring a variable on one element and expecting a sibling to see it.
      • 
        
    • A space after var( in the name, or a missing --.
      • 
        
    • Expecting a bad value in a variable to be ignored like a normal invalid declaration.
