What's in the Head? Web Page Metadata

Nothing in the head shows on the page, but it decides what the browser tab says, how the text is decoded, what search results and shared links look like, and which CSS and JavaScript load.

You'll be able to

  • Explain what belongs in the head and what belongs in the body.
  • Write a title, a character set, and author and description metadata.
  • Add a favicon, and link a stylesheet and a script the right way.
  • Set the page's language, and mark up phrases in other languages.
Read

What is the HTML head?

Every page has two parts. The <body> holds everything visitors see. The head holds information about the page, called metadata, that the browser uses but doesn't display:

<!doctype html>
<html lang="en-US">
  <head>
    <meta charset="utf-8">
    <title>Royal Arch Trail | Boulder Trail Club</title>
  </head>
  <body>
    <h1>Royal Arch Trail</h1>
  </body>
</html>

Real pages often have a dozen or more lines in the head. This lesson covers the ones you'll use on every page.

Adding a title

Two elements sound alike but do different jobs. The <h1> is the big heading on the page. The <title> goes in the head and names the page everywhere else: the browser tab, bookmarks, history, and the blue link in search results.

Put the most specific words first, so they still show in a crowded tab bar: Royal Arch Trail | Boulder Trail Club beats Boulder Trail Club | Hikes | Royal Arch. And never leave it as "Untitled" or "Home".

Metadata: the <meta> element

  

    
Most metadata goes in <meta> elements. They're void elements: no content, no closing tag. Most have a name saying what kind of information it is and a content holding the information.

    
Specifying your document's character encoding

    
A file is just bytes. <meta charset="utf-8"> tells the browser how to turn those bytes back into letters. UTF-8 covers nearly every writing system, so put it first in every head. With the wrong encoding, anything beyond plain English letters turns into gibberish. Try it below.

    
Adding an author and description

    
<meta name="author" content="Boulder Trail Club">
<meta name="description" content="A steep 3.4-mile round trip to a sandstone arch above Chautauqua, with views over Boulder.">

    
The meta description often becomes the grey text under your link in search results, so write it for people: one or two sentences, about 70 to 160 characters. You may see a keywords meta tag in old code. Search engines ignore it.

    
Other types of metadata

    
Sites like Facebook, Slack and Discord read Open Graph tags to build the preview card when someone shares your link. They use property instead of name:

    
<meta property="og:title" content="Royal Arch Trail">
<meta property="og:image" content="https://trailclub.github.io/images/royal-arch.jpg">

    
Watch out
og:image needs a full https:// address. Another company's server fetches the image, and it doesn't know where your page lives, so a relative path like images/arch.jpg won't work.

Adding custom icons to your site
A favicon is the little picture in the browser tab and in bookmarks. One SVG covers most browsers; add a PNG for phones that save your site to their home screen.

  

    
1. Make a square image
Use a simple shape or one or two letters. Fine detail disappears at 16 × 16 pixels. Save it as favicon.svg, or as a 32 × 32 favicon.png.

    
2. Link it in the head
<link rel="icon" href="favicon.svg" type="image/svg+xml">
rel says how the linked file relates to the page.

    
3. Add a home-screen icon
<link rel="apple-touch-icon" href="icon-180.png" sizes="180x180">
A 180 × 180 PNG, used when someone adds your site to a phone's home screen.

Applying CSS and JavaScript to HTML

  

    
Styles and scripts usually live in their own files, linked from the head:

    
<link rel="stylesheet" href="css/style.css">
<script src="js/trail.js" defer></script>

    
<link> is a void element. <script> isn't: it always needs its closing tag, even when it's empty.

    
The browser reads a page from top to bottom. When it reaches a plain <script>, it stops and runs the script straight away, before the rest of the page exists. A script that tries to change a heading further down can't find it. The defer attribute fixes that: the script downloads in the background and runs once the whole page has been read.

    Setting the primary language of the document
    
  
    
    
    The lang attribute on <html> says what language the page is written in. Screen readers use it to pick the right voice and pronunciation, and search engines and translation tools use it too. Use a short language code like en, or add a region: en-US, es-MX.
    
    
    When one phrase is in a different language, mark just that phrase. A screen reader then switches pronunciation for it and back again:
    
    
    <p>The garden's name is <span lang="ja">日本庭園</span>, "Japanese garden".</p>

    Key ideas
    
      
      
        
    • The head holds metadata: information about the page that isn't shown on it.
      • 
        
    • <title> names the page in tabs and search results; <h1> is the heading on the page.
      • 
        
    • Put <meta charset="utf-8"> first in every head.
      • 
        
    • <meta name="…" content="…"> adds an author, a description and more. Open Graph tags use property.
      • 
        
    • Link CSS with <link rel="stylesheet"> and JavaScript with <script src defer></script>.
      • 
        
    • Set lang on <html>, and on any phrase in another language.
      • 
      
    
    
    
    
    
      
    Common mistakes
    
      
      
        
    • Putting visible content, like a heading or an image, in the head.
      • 
        
    • Leaving the title as "Untitled" or "Home", which says nothing in a row of tabs.
      • 
        
    • Writing <script src="…"> without </script>. Everything after it is swallowed.
      • 
        
    • A script in the head without defer that can't find elements on the page.
      • 
        
    • A relative path for og:image. It must be a full https:// URL.
      •
