Functions

A function is a named block of code you can run whenever you need it. You'll use the browser's built-in functions, write your own, pass values in and get values back.

Functions: reusable blocks of code

A function is a named block of code that you can run whenever you need it, as many times as you like. You pass values in, it does some work, and it can hand a value back.

function hikeTime(miles, pace = 2) {
  return miles / pace;
}
const hours = hikeTime(6, 3);   // 2

The names in the definition, miles and pace, are parameters: placeholders waiting for values. The values you pass when you call it, 6 and 3, are arguments. pace = 2 is a default, used when no second argument is given.

To run a function, you call it with parentheses: hikeTime(6, 3). Without the parentheses, hikeTime just refers to the function itself without running it, which is exactly what you want when you pass it to an event listener, but a bug everywhere else.

return sends a value back to wherever the function was called, and ends the function right there. Forget the return and the function still runs, but its return value is undefined.

You'll see functions written several ways. The arrow function is the short version: const hikeTime = (miles, pace = 2) => miles / pace;. It does the same thing.

Variables declared inside a function only exist inside it. That's called scope, and it's a good thing: two functions can each have their own total without interfering with each other.

Tip

A good function does one job and is named with a verb that says what: hikeTime(), showError(), addTrail().

Built-in browser functions

You've been using functions since your first line of JavaScript. Every time you write something with parentheses after it, you're calling one:

const myText = "I am a string";
const newString = myText.replace("string", "sausage");   // "I am a sausage"

const myArray = ["I", "love", "chocolate", "frogs"];
const madeAString = myArray.join(" ");                   // "I love chocolate frogs"

const myNumber = Math.random();                          // between 0 and 1

These are built into the language or the browser. Someone wrote them once so you don't have to.

Functions versus methods

A function that belongs to an object is called a method. replace() belongs to strings, join() to arrays, random() to the Math object. You'll learn more about objects in the next lesson. For now, a method is just a function you call with a dot in front of it.

Custom functions

The functions you write yourself, with the function keyword and a name of your choosing, are custom functions. hikeTime() above is one.

Invoking functions

Defining a function doesn't run it. You run it (call or invoke it) by writing its name followed by parentheses. You can call it as many times as you like.

Function parameters

Some functions need information to do their job. Math.random() needs nothing; myText.replace("string", "sausage") needs two things: what to find and what to put in its place. Those values are arguments; the names that receive them inside the definition are parameters.

Optional parameters

Some built-in parameters are optional. join() without an argument uses a comma: ["a", "b"].join() gives "a,b".

Anonymous functions and arrow functions

  


A function doesn't need a name. An anonymous function is usually passed straight into another function that will call it later. Here, addEventListener() calls it whenever a key is pressed:

    
textBox.addEventListener("keydown", function (event) {
  console.log(`You pressed "${event.key}".`);
});

    
An arrow function is a shorter way to write the same thing: drop function and put => after the parameters:

    
textBox.addEventListener("keydown", (event) => {
  console.log(`You pressed "${event.key}".`);
});

Function scope and conflicts

  


Variables created inside a function only exist inside it: that's the function's scope. Code outside can't see them. Variables declared outside every function are in the global scope and can be seen everywhere.

    
That's useful. If two scripts on the same page both had a global name, one would overwrite the other. Inside functions, each can have its own total or name without clashing.

Build your own function

  


MDN's walkthrough builds a displayMessage() function that pops up a message box. It starts with no parameters, always showing the same text, then gains a msgText parameter for the message and a msgType parameter for the style. That's the general pattern: get it working for one case, then turn whatever changes into a parameter.

    
function displayMessage(msgText, msgType) {
  const panel = document.createElement("div");
  panel.setAttribute("class", "msg-box");
  html.appendChild(panel);

  const msg = document.createElement("p");
  msg.textContent = msgText;
  panel.appendChild(msg);
  // … a close button, and a class for msgType
}

btn.addEventListener("click", () => displayMessage("Brr, it's cold!", "warning"));

    
Notice the last line: addEventListener needs a function to call later, so you wrap the call in an arrow function. Writing displayMessage(…) directly would run it immediately.

Function return values

  


What are return values?

    
Some functions hand a value back when they finish: myText.replace("string", "sausage") returns the new string, which you can store in a variable. Others, like displayMessage(), just do something and return nothing (strictly, they return undefined).

Key ideas

      
    
        
  • A function is a named, reusable block of code. A method is a function that belongs to an object.
    • 
        
  • Parameters are the names in the definition; arguments are the values you pass in.
    • 
        
  • Default parameters fill in missing arguments: function greet(name = "friend").
    • 
        
  • Anonymous and arrow functions are often passed to other functions, like map() or addEventListener().
    • 
        
  • return sends a value back and ends the function. Variables declared inside a function stay inside it.

Common mistakes

      
    
        
  • Using console.log() where you meant return. The value is printed, but the caller gets undefined.
    • 
        
  • Passing a call instead of a function: btn.addEventListener("click", go()) runs go right away.
    • 
        
  • Using a variable declared inside a function from outside it: ReferenceError.
    • 
        
  • Putting code after return and expecting it to run.
