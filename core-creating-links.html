Creating Links

Links are what make the web a web. Write links to other pages, other sites, spots on a page, files and email addresses, with paths that find their target and text that says where it goes.

You'll be able to

  • Write a link with <a href>, around text, a heading or an image.
  • Write relative paths into folders, out of folders, and from the site's root.
  • Link to another site with a full URL, and to a spot on a page with a fragment.
  • Write clear link text, and signpost downloads and new tabs.
  • Build a navigation menu and an email link.

Anatomy of a link

A hyperlink connects a page to any other document or resource that has a URL. You make one by wrapping content in an <a> (anchor) element and putting the destination in its href (hypertext reference) attribute:

<p>Start with the <a href="https://www.nps.gov/romo/">Rocky Mountain National Park website</a>.</p>

Block level links and image links

Almost anything can be a link, not just text. Wrap a heading to make the whole heading clickable, or wrap an image to make a clickable logo. An image link's alt text becomes the link's text, so describe where it goes:

<a href="index.html">
  <img src="logo.svg" alt="Boulder Trail Club home page">
</a>

Adding supporting information with the title attribute

A title attribute shows a tooltip when the mouse hovers over the link. Don't rely on it: keyboard and touchscreen users never see it, and many screen readers skip it. Anything important belongs in the link text.

A quick primer on URLs and paths

A path is directions from the page you're writing in to the file you want. Picture your site's folders:

  • Same directory: just the file name. about.html
  • Moving down into subdirectories: folder, slash, file. trails/mesa.html
  • Moving back up into parent directories: ../ means "the folder above". ../index.html, or ../../index.html for two levels.
  • Linking relative to the root directory: a leading slash starts at the top of the site. /images/logo.png
  • Linking with full URLs: for another site, write the whole absolute path, starting with https://.

The first four are relative paths: they work inside your own site, wherever it's hosted. Links within your site are internal; links to other sites are external and always need a full URL.

Watch out

Paths starting with / break on GitHub Pages project sites, which live in a folder like you.github.io/trail-club/. Stick to relative paths for your own files.

      Document fragments

      A link can jump to a spot on a page. Give the target element an id, then add # and that id to the end of the link. On the same page, the # part is enough:

      <h2 id="parking">Parking</h2>
…
<a href="#parking">Where to park</a>
<a href="trails/mesa.html#parking">Mesa Trail parking</a>

      And when a URL ends in a folder, like trails/, the server sends that folder's index.html.

      Link best practices
      
  
      
    
      Use clear link wording
      
    
      Screen reader users often pull up a list of every link on the page, and sighted readers skim for blue text. "Click here" means nothing out of context. Make the link text say where it goes: <a href="…">Download the trail map</a>, not Click <a href="…">here</a>. Don't use the raw URL as the text either, and keep it short.
      
    
      Linking to non-HTML resources: leave clear signposts
      
    
      If a link downloads a big file or opens a PDF, say so in the text: Trail map (PDF, 2 MB). Nobody likes a surprise download on a phone plan.
      
    
      Use the download attribute when linking to a download
      
    
      download tells the browser to save the file instead of opening it, and can suggest a file name: <a href="maps/mesa.pdf" download="mesa-trail-map.pdf">.
      
    
      When to open links in a new tab
      
    
      target="_blank" opens a link in a new tab. Use it sparingly. It takes the choice away from the visitor, and the back button stops working. If you do, say so in the link text.

      Creating a navigation menu
      
  
      
    
      A site's main menu is a list of links, usually wrapped in <nav>. The same menu goes on every page. On the current page, its own item is often left as plain text, or marked with aria-current="page", so it isn't a link to where you already are:
      
    
      <nav>
  <ul>
    <li><a href="index.html">Home</a></li>
    <li><a href="trails.html" aria-current="page">Trails</a></li>
    <li><a href="about.html">About</a></li>
  </ul>
</nav>

      Email links
      
  
      
    
      A link whose href starts with mailto: opens the visitor's email app with a new message: <a href="mailto:hello@trailclub.org">Email the club</a>. You can fill in more of the message after a ?: subject, cc, bcc and body, joined with &. Spaces and special characters must be encoded: a space becomes %20.

      Key ideas
      
      
        
        
      • A link is <a href="destination">content</a>. Text, headings and images can all be links.
        • 
        
      • file.html stays in this folder, folder/file.html goes in, ../file.html goes up.
        • 
        
      • Other sites need a full URL: https://….
        • 
        
      • #id jumps to the element with that id.
        • 
        
      • Link text should make sense on its own, and warn about downloads and new tabs.
        • 
      
      
    
      
    
      
      
      Common mistakes
      
      
        
        
      • "Click here" or "read more" as link text.
        • 
        
      • Linking another site without https://, so it's treated as a file in your folder.
        • 
        
      • Paths from your own computer, like file:///Users/… or C:\….
        • 
        
      • A capital letter in the path that doesn't match the file name.
        • 
        
      • Opening every link in a new tab.
        •
