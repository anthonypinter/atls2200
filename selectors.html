Selectors & Specificity

A selector picks which elements a rule applies to. Type one below and the matching elements light up. When two rules disagree, specificity decides which one wins.

You'll be able to

  • Select elements by type, class, ID and attribute.
  • Combine selectors with descendant, child and sibling combinators.
  • Work out which of two rules wins using specificity.
Read

Picking the right elements

A selector is how a rule says which elements it styles. Three kinds do most of the work:

  • A type selector like p picks every paragraph.
  • A class selector like .card picks every element with class="card". Classes are reusable, so they're what you'll use most.
  • An ID selector like #top picks the one element with id="top".

You can combine them. A combinator describes how elements relate:

.card .title { }   /* a .title anywhere inside a .card */
.card > h2 { }     /* an h2 that's a direct child of .card */
h2 + p { }         /* the p right after an h2 */
.tag.hard { }      /* one element with both classes */

Look closely at the first and last lines. A space means "inside", and no space means "both at once". That one space is behind a lot of confusing bugs. An attribute selector, like a[href$=".pdf"], picks elements by their attributes: here, links to PDF files.

When two rules set the same property on the same element, specificity decides which wins. The browser scores each selector by counting IDs, then classes, then element types, and compares column by column. One ID outranks any number of classes, and one class outranks any number of types. Only if the scores tie does the rule written later win.

Tip

Style with classes and keep selectors short. IDs and long chains score so high that the next time you want to change something, you'll need an even stronger selector to beat them.

Key ideas

  • A space means "inside, at any depth." > means "a direct child only."
  • No space between parts means "both at once": .tag.hard is an element with both classes.
  • A comma makes a list: h2, .btn matches either one.
  • + and ~ only look forward at later siblings, never back up or into children.
  • Score order: IDs beat classes, classes beat elements. One ID outranks any number of classes.
  • Inline style="" beats all selectors, and !important beats that. Avoid both when you can.

Common mistakes

  • Forgetting the dot: card looks for a <card> element, not class="card".
  • Writing .card.title when you meant .card .title. One space changes everything.
  • Styling with IDs everywhere, then needing even stronger selectors to override them.
  • Reaching for !important instead of finding out why a rule is losing.
