Organizing CSS

A stylesheet that works today can still be a nightmare to change next week. Watch one messy stylesheet get cleaned up in four steps. It styles exactly the same page at every step; only how easy it is to work with changes.

You'll be able to

  • Group a stylesheet into sections in a consistent order.
  • Name classes after what something is, not how it looks.
  • Replace repeated values with CSS variables and keep specificity low.
Read

A stylesheet you can come back to

CSS doesn't care how your file is arranged. You do, the next time you need to change something and can't find it. A few habits keep a stylesheet easy to work with as it grows.

Sections, always in the same order. A common order runs from general to specific: CSS variables first, then base styles for plain elements like body and a, then layout, then components like cards and buttons, then small utility classes. Mark each section with a comment heading. Because later rules win ties, this order also means the specific stuff naturally overrides the general.

/* ===== Base ===== */
body { font-family: var(--font-body); }

/* ===== Components ===== */
.trail-card { … }

Names that describe purpose. .trail-card still makes sense after the redesign; .blue-box doesn't, once the box turns green. A popular naming pattern called BEM spells out how pieces relate: .card, .card__title, .card--featured.

No repeated values. If you've typed the same color three times, make it a variable. Changing it later becomes a one-line edit.

Low, even specificity. Style with single classes. IDs and long chains like #main .content ul li a are hard to override, which leads to even longer selectors, and eventually !important.

Tip

Delete rules you no longer use. Keeping them "just in case" makes every future change slower. If you need them back, they're in your version history.

Key ideas

      
    
        
  • Group rules into sections with comment headings, always in the same order.
    • 
        
  • Name classes after their purpose: .trail-card, not .blue-box.
    • 
        
  • BEM is a popular naming pattern: .block, .block__element, .block--variation, like .card__title and .btn--large.
    • 
        
  • Any color or size you type more than twice should probably be a CSS variable.
    • 
        
  • Prefer classes over IDs and long chains of selectors. Low, even specificity is easier to override.
    • 
      

    

    

      
Common mistakes

      
    
        
  • Adding every new rule to the bottom of the file.
    • 
        
  • Names like .box2, .new or .left that stop making sense later.
    • 
        
  • The same rule written twice in different places, with slightly different values.
    • 
        
  • Leaving old, unused rules in "just in case." Delete them; that's what version control is for.
