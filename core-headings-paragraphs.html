Headings and Paragraphs

Headings and paragraphs give text its shape. Learn the six heading levels, how to nest them into an outline, and why that outline matters to readers, screen readers and search engines.

You'll be able to

  • Mark up text with <h1>–<h6> and <p>.
  • Build a heading outline: one <h1>, no skipped levels.
  • Explain why structure helps people skim, screen readers navigate, and search engines rank.
  • Choose elements for what they mean, not how they look.

Headings and paragraphs

Most text on the web is headings and paragraphs. A paragraph goes in a <p> element:

<p>The Mesa Trail runs along the foot of the Flatirons for 6.7 miles.</p>

A heading goes in one of six heading elements, <h1> through <h6>. The number is the heading's level: <h1> is the main heading of the page, <h2>s are its sections, <h3>s are sections inside those, and so on.

<h1>Mesa Trail</h1>
<h2>Getting there</h2>
<h3>Parking</h3>

Implementing structural hierarchy

Headings nest like a table of contents. A trail guide might look like this:

<h1>Boulder Trail Guide</h1>
<p>Twelve hikes within half an hour of town.</p>

<h2>Easy hikes</h2>
<h3>Bobolink Trail</h3>
<p>Flat, shady and good for kids.</p>

<h2>Hard hikes</h2>
<h3>Bear Peak</h3>
<p>A steep 2,800-foot climb.</p>

Three rules keep an outline easy to follow:

  • One <h1> per page. It's the page's title.
  • Don't skip levels. An <h2> section's subsections are <h3>s, never <h4>s.
  • Keep it shallow. More than three levels gets hard to follow. If you need <h5>, split the page instead.

      Why do we need structure?

      Browsers don't guess. Text typed into an HTML file without elements comes out as one long run of words, because whitespace collapses. Headings and paragraphs fix that, and they help in ways you can't see:

      • People skim. Readers look for the heading that matches what they want and jump straight there.
      • Screen readers navigate by headings. A screen reader user can list a page's headings and jump between them, the way you'd glance down a page.
      • Search engines read headings to work out what a page is about.
      • CSS and JavaScript need something to target. You can style every <h2> at once, but you can't style "the line that's sort of a title".

      Why do we need semantics?
      
  
      
    
      You could make any text look like a heading with CSS: big and bold. But looking like a heading isn't the same as being one:
      
    
      <span style="font-size: 32px; font-weight: bold">Mesa Trail</span>
      
    
      Sighted visitors see a heading. A screen reader sees an ordinary bit of text: it isn't in the headings list, so nobody can jump to it. Search engines don't treat it as important either. That's what semantic HTML means: choosing elements for what the content is, then using CSS for how it looks.
      
    
      Watch out
      The opposite mistake is just as common: picking <h4> because it's the size you want. Choose the level that fits the outline, then change the size with CSS.

      Key ideas
      
      
        
        
      • Paragraphs go in <p>; headings go in <h1>–<h6>.
        • 
        
      • One <h1> per page, then <h2> sections, <h3> subsections.
        • 
        
      • Never skip a level going down. Jumping back up (h3 to h2) is fine.
        • 
        
      • Screen reader users navigate by headings, and search engines read them.
        • 
        
      • Pick elements for meaning; change their look with CSS.

      Common mistakes
      
      
        
        
      • Choosing a heading level for its size instead of its place in the outline.
        • 
        
      • Big bold text in a <span> or <p> instead of a real heading.
        • 
        
      • Several <h1>s on one page.
        • 
        
      • Using empty <p></p> or <br>s to add space. That's CSS's job.
