Styling Lists, Tables and Forms

Lists, tables, images and form controls each come with their own default styling quirks. This lesson tames them: custom bullets, readable tables, images that fit their boxes, and forms that match the rest of the page.

You'll be able to

  • Style list markers, spacing and counting.
  • Make a data table readable with spacing, alignment, borders and zebra stripes.
  • Fit images into boxes with max-width and object-fit.
  • Normalise form controls so they inherit fonts and size predictably, then style them.

Styling lists

Handling list spacing

Browsers give lists a top and bottom margin and about 40px of left padding, which is where the bullets sit. Set the spacing yourself so lists line up with your paragraphs: matching line-height and margins on p and li keeps the rhythm even.

List-specific styles

  • list-style-type: the bullet or numbering style: disc, circle, square, decimal, lower-alpha, upper-roman, none, or any string like "→ ".
  • list-style-position: outside (the default; the marker hangs in the padding) or inside (the marker sits in the text, which wraps under it).
  • list-style-image: an image as the bullet. You can't size it, so many people use ::marker or a background image instead.
  • list-style: the shorthand, as in list-style: square inside;.

Controlling list counting

In the HTML, <ol start="4"> starts counting at 4, reversed counts down, and <li value="2"> sets one item's number.

Styling tables

  


A well-structured table (Week 2) is the starting point. Then a handful of rules makes it readable:

    
    
      
  • Font: a clean sans-serif is easiest to scan.
    • 
      
  • Spacing: border-collapse: collapse merges double borders; padding on cells gives the data room; table-layout: fixed with a width makes column widths predictable.
    • 
      
  • Alignment: left-align text, right-align numbers so their digits line up, and vertical-align: top for cells of different heights. :nth-child() picks the column.
    • 
      
  • Borders: a few lines, like one under the header and one above the totals, beat a grid of boxes.
    • 
      
  • Zebra striping: tbody tr:nth-child(odd) shades alternate rows, so eyes don't slip to the wrong row.
    • 
      
  • Caption: caption-side: bottom moves it under the table.
    •

Images and media

  


Replaced elements

    
Images and videos are replaced elements: their content comes from an outside file, and CSS can't change what's inside them, only the box they sit in.

    
Sizing images

    
An image is shown at its natural size, so a large photo overflows its container. One rule stops that everywhere:

    
img {
  max-width: 100%;
  height: auto;
}

    
Handling image display issues with object-fit

    
When you force an image into a box of a different shape, it stretches. object-fit controls how it fills the box instead: cover fills it and crops; contain fits the whole image and leaves gaps; fill (the default) stretches.

    
Replaced elements in layout

    
In layouts like Grid, items normally stretch to fill their area, but images keep their own proportions. Give the image width: 100%; height: 100%; object-fit: cover; if you want it to fill its cell.

Styling form elements

  


Challenges in styling form widgets

    
Form controls started out drawn by the operating system, not the browser, and some still are. They fall into three groups:

    
    
      
  • Easy to style: text inputs, <textarea>, <button>, <fieldset> and <legend> behave like ordinary boxes.
    • 
      
  • Harder: checkboxes and radio buttons. accent-color recolours them in one line.
    • 
      
  • Mostly unstylable inside: colour and date pickers, range sliders, file inputs, <select> dropdowns, <progress> and <meter>. You can size the box, but not much of what's inside.
    • 
    

    
Normalising form behaviour: a reset

    
Form controls don't inherit the page's font, and their sizing differs between browsers. A short reset fixes both:

    
button, input, select, textarea {
  font-family: inherit;
  font-size: 100%;
  box-sizing: border-box;
}
textarea {
  overflow: auto;
}

    
Styling text inputs

    
Then style them like any box: border, padding, border-radius. Put each label above its input, make the input full width, and give :focus-visible a clear outline. Keep controls recognisable: an input that doesn't look like an input won't get filled in.

    
Watch out
Don't show errors with colour alone. Some visitors can't tell red from green. Add a text message next to the field explaining what's wrong.

Key ideas

      
    
        
  • list-style-type, -position and -image (or ::marker) style list markers.
    • 
        
  • Tables: collapse borders, pad cells, right-align numbers, stripe rows with :nth-child(odd).
    • 
        
  • img { max-width: 100%; height: auto; } stops images overflowing.
    • 
        
  • object-fit: cover fills a box without stretching the image.
    • 
        
  • Form controls need font: inherit and box-sizing: border-box to match the page.
    • 
      

    

    

      
Common mistakes

      
    
        
  • Removing list padding with markers outside, so the bullets disappear off the edge.
    • 
        
  • Centring numbers in a table, so digits don't line up.
    • 
        
  • Setting a width and height on an image without object-fit, so it stretches.
    • 
        
  • Restyling form controls until they no longer look like form controls.
    • 
        
  • Removing the focus outline from inputs.
    •
