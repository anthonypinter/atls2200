Video and Audio

The <video> and <audio> elements play media without any plugins. Their attributes decide what visitors see, what plays by itself, and which file the browser picks.

You'll be able to

  • Add video and audio with controls and fallback content.
  • Offer more than one file format with <source>.
  • Use poster, muted, autoplay, loop and preload well, and explain why browsers block autoplay with sound.
  • Add captions with a WebVTT file and <track>.

Video and audio on the web

Early websites needed plugins like Flash to play video, and they were slow, insecure and didn't work on phones. Today the browser plays media itself, through two elements that work almost identically: <video> and <audio>.

Video files are big. For long videos, hosting on YouTube or Vimeo and embedding them is often easier. For short clips, backgrounds and audio you own, these elements are the way.

The <video> element

<video src="mesa.webm" controls>
  <p>Your browser can't play this video. <a href="mesa.webm">Download it</a> instead.</p>
</video>
  • src is the path to the file, just like an image.
  • controls adds the browser's play button, timeline and volume. Leave it out and visitors can't pause or mute, so always include it unless you build your own.
  • Anything between the tags is fallback content, shown only by browsers that can't play video at all.

Using multiple source formats to improve compatibility

Contents of a media file

A video file is a container (MP4, WebM, Ogg) holding tracks: usually one video track and one audio track. Each track is compressed with a codec, like H.264 or AV1 for video and AAC or Opus for audio. The extension tells you the container, not the codecs inside.

mesa.mp4 (container)
Video track · H.264
Audio track · AAC

Media file support in browsers

Not every browser can decode every codec, partly because some are patented. The fix: drop src from the <video> and list several <source> elements instead. The browser tries them in order and plays the first one it can:

<video controls>
  <source src="mesa.webm" type="video/webm">
  <source src="mesa.mp4" type="video/mp4">
  <p>Your browser can't play this video.</p>
</video>

The type lets the browser skip files it can't play without downloading them. MP4 with H.264 plays almost everywhere, so it makes a good last option.

    Other <video> features

    • width and height reserve space, like on an image.
    • poster shows an image until the video starts, instead of a black box.
    • autoplay starts playing straight away. Browsers block autoplay with sound, so it only works together with muted. Use it sparingly.
    • muted starts with the sound off.
    • loop starts again at the end.
    • preload hints how much to download before anyone presses play: none, metadata (just the length and size) or auto.

    The <audio> element

    <audio> works the same way as <video>, with controls, <source>s and fallback content. Since there's no picture, it doesn't take width, height or poster.

    <audio controls>
  <source src="ranger-talk.mp3" type="audio/mpeg">
  <source src="ranger-talk.ogg" type="audio/ogg">
  <p><a href="ranger-talk.mp3">Download the talk</a></p>
</audio>

    For audio-only content, like a podcast, provide a written transcript on the page as well.

    Displaying video text tracks

    People who are deaf or hard of hearing, people watching on mute, and people who don't speak the video's language all need its words as text. Those words live in a separate WebVTT file (.vtt), linked with <track> inside the video:

    <track kind="captions" src="mesa.vtt" srclang="en" label="English">

    kind can be subtitles (a translation), captions (the dialogue plus important sounds, like "[thunder]") or descriptions (what's happening on screen, for people who can't see it).

    Key ideas

    • Always include controls unless you build your own play button. Without it, people can't pause or adjust volume.
    • Browsers block autoplay with sound. Autoplay only works with muted, and should be rare.
    • List more than one <source> (like MP4 and WebM) and the browser plays the first one it supports.
    • Add captions for videos and a transcript for audio, for people who can't hear it and everyone watching on mute.
    • <audio controls> works the same way, without the picture.

    Common mistakes

    • Uploading a huge video file straight from a phone. Compress it, or host it on YouTube or Vimeo and embed it.
    • Expecting autoplay to work without muted.
    • No poster, so the player shows a black box until it loads.
    • Background videos that loop forever with no way to pause them.
    • Getting the type wrong on a <source>, so the browser skips a file it could have played.
