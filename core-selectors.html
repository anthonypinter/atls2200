Selectors

Every CSS rule starts with a selector: the part that says which elements to style. Choose them by type, by class or id, by attribute, or by where they sit in the page.

You'll be able to

  • Select elements by type, class and id, and combine them in a selector list.
  • Use the universal selector and chain classes onto one element.
  • Select elements by attribute, including the start, end or middle of its value.
  • Use descendant, child and sibling combinators to target elements by position.
Read

What is a selector?

A selector is the first part of a rule, before the braces. The elements it matches are called its subject, and those are the elements the declarations style.

h1 { color: navy; }   /* subject: every h1 */
.box { padding: 1em; } /* subject: every element with class="box" */

Type, class and ID selectors

Type selectors

A type selector is just an element name: span, strong, em. It matches every element of that type.

Class selectors

A class selector is a dot followed by a class name. .highlight matches every element with class="highlight", whatever its type. Classes are reusable, so they're what you'll use most.

  • On a particular element: span.highlight matches only spans with that class; h1.highlight only headings.
  • More than one class: an element can have several, separated by spaces: class="notebox warning". Chain them with no space to match elements with both: .notebox.warning.

ID selectors

An ID selector is a hash followed by an id: #one matches the element with id="one". An id should appear only once per page, so an ID selector styles one element. Classes are usually the better choice: they're reusable and easier to override.

Selector lists

When several selectors share the same declarations, list them with commas instead of repeating the rule:

h1,
.special {
  color: blue;
}

Careful: if any selector in a list is invalid, the whole rule is thrown away. h1, ..special { } styles nothing at all, not even the h1s.

The universal selector

An asterisk, *, matches everything. On its own, * { margin: 0; } removes the margin from every element. Inside a selector it can make your meaning clearer: article :first-child (with a space) and article *:first-child mean the same thing, "any first child inside an article", but the second is much harder to misread as article:first-child.

Attribute selectors

An attribute selector matches elements by their attributes, written in square brackets.

Presence and value selectors

[attr]has the attribute at all: a[title]
[attr="value"]the value is exactly this: input[type="email"]
[attr~="value"]one of its space-separated words is exactly this
[attr|="value"]exactly this, or this followed by a hyphen: [lang|="en"] matches en and en-US

Substring matching selectors

[attr^="value"]starts with: a[href^="https"]
[attr$="value"]ends with: a[href$=".pdf"]
[attr*="value"]contains anywhere: [class*="card"]

    Combinators

    A combinator joins two selectors and says how the elements relate:

    • Descendant (a space): .box p matches a p anywhere inside .box, however deeply nested.
    • Child (>): ul > li matches only lis that are direct children of a ul, not ones in a nested list.
    • Next-sibling (+): h1 + p matches a p that comes straight after an h1, with the same parent.
    • Subsequent-sibling (~): h1 ~ p matches every p anywhere after an h1, with the same parent, even with other elements in between.

    Combining combinators with selectors

    Any selector can sit on either side: ul > li.a, .card h2 + p. Read them right to left: "a p, straight after an h2, inside a .card".

    Watch the spaces

    .tag .hard (with a space) means "a .hard inside a .tag". .tag.hard (no space) means "one element with both classes". That one space is behind a lot of confusing bugs.

    Key ideas

    • Type selectors match an element name; .class matches a class; #id matches one element.
    • Chain with no space (.a.b) for elements that have both; separate with commas for a list.
    • Attribute selectors use square brackets: ^= starts, $= ends, *= contains.
    • Combinators: space (inside), > (direct child), + (right after), ~ (any later sibling).
    • Prefer classes. IDs and long chains are hard to override later.

    Common mistakes

    • A stray space: .tag .hard when you meant .tag.hard.
    • Forgetting the dot: card { } looks for a <card> element.
    • One typo in a selector list, which throws away the whole rule.
    • Reusing an id on several elements instead of using a class.
    • Expecting h1 + p to match a paragraph that isn't directly after the heading.
