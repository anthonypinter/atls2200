Building for everyone

Accessibility means people can use your site however they use the web: with a mouse, a keyboard, a screen reader that reads the page aloud, zoomed in to 200%, or on a phone in bright sun. Plenty of visitors depend on these, and an accessible site is easier for everyone else, too.

Most of the work is done by choosing the right HTML element. A real <button> can be reached with Tab, pressed with Enter or Space, and is announced as "button." A <div> with a click handler does none of that. The same goes for links, headings, lists and form labels: semantic HTML brings accessibility with it for free.

Four checks catch most problems:

  • Keyboard. Put your mouse away and press Tab through the page. Can you reach and use everything? Can you see where you are? Never remove the focus outline without adding a replacement.
  • Names. Every control needs a name a screen reader can say: a label for each input, text inside each button, alt text on each meaningful image.
  • Color. Text needs enough contrast with its background, at least 4.5 to 1 for normal text. And don't use color alone to carry meaning, like red for errors.
  • Structure. Use one <h1> and headings in order, so people can jump around the page by heading.

Tip

Placeholder text isn't a label. It disappears as soon as someone starts typing, and it's usually too pale to read. Use a real <label>.

    Key ideas

    • Use the right HTML element first. Real buttons, links, labels and headings come with accessibility built in.
    • Everything you can do with a mouse should work with a keyboard.
    • Every control needs a name a screen reader can say: label text, button text or alt text.
    • Don't use color alone to show meaning, like red for errors. Add text or an icon.

    Common mistakes

    • Clickable divs and spans. They can't be reached with Tab.
    • outline: none with no replacement focus style.
    • Placeholder text used as the only label.
    • Pale gray text because it "looks clean."
