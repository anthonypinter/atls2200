SVG and Embedded Content

Two ways to bring more than text and photos into a page: SVG, images written as code that stay sharp at any size, and iframes, windows that show a whole other page, like a YouTube video or a map.

You'll be able to

  • Explain the difference between raster and vector images.
  • Read and edit simple SVG, and add it to a page with <img> or inline.
  • Embed a video or map with an <iframe>, with a title, lazy loading and responsive sizing.
  • Explain the security risks of embedding, and what sandbox does.

What are vector graphics?

Images come in two kinds:

  • Raster images (JPEG, PNG, WebP) are grids of pixels. Blow one up and you see the squares.
  • Vector images are instructions: "a circle here, this big, this colour". The browser draws them fresh at whatever size is needed, so they're always sharp, and simple ones are tiny files.

What is SVG?

SVG (Scalable Vector Graphics) is a markup language for drawing, written in tags just like HTML:

<svg viewBox="0 0 100 100" width="100" height="100">
  <circle cx="50" cy="50" r="45" fill="#0b6b5e" />
  <path d="M20 72 L45 35 L58 52 L66 42 L82 72 Z" fill="#fff" />
</svg>

viewBox sets up the drawing's own coordinate system, here 100 × 100 units; the shapes use those units whatever size the SVG is shown at. Elements like <rect>, <circle>, <line>, <text> and <path> draw shapes.

You'll rarely write complex SVG by hand: design tools like Figma, Illustrator and Inkscape export it. SVG is great for logos, icons and diagrams. It's no good for photos, which can't be described as shapes.

Adding SVG to your pages

The quick way: <img>

<img src="badge.svg" alt="Boulder Trail Club" width="100" height="100">

Familiar, cached by the browser, and it takes alt text. But CSS and JavaScript can't reach inside, so you can't change its colours on hover.

Troubleshooting

Every current browser shows SVG. If an SVG in an <img> doesn't appear, check the path, and check the file has xmlns="http://www.w3.org/2000/svg" on its <svg> tag: files need it, inline SVG doesn't.

Including SVG code inside your HTML

Paste the <svg> straight into your page. Now CSS can restyle its parts and there's no extra download. The cost: it isn't cached separately, and it clutters your HTML. For accessibility, give it role="img" and a <title> as its first child, which works like alt text.

Embedding an SVG with an <iframe>

Possible, but it has all the drawbacks of iframes and none of the benefits of the other two. Don't.

A short history of embedding

The early web tried many ways to put one thing inside another: frames that split the window into separate pages, then plugins like Java applets and Flash for anything interactive. Frames broke bookmarks and the back button; plugins were slow and insecure, and didn't work on phones. They're gone. What survived is the iframe: a window in your page that shows another web page.

Playing with classic embedding uses

The services you'll most often embed give you the code from a Share or Embed button:

<iframe src="https://www.youtube.com/embed/VIDEO_ID"
        title="Hiking the Mesa Trail, a 3-minute tour"
        width="560" height="315" loading="lazy"></iframe>

The src must be the embed address, like youtube.com/embed/…, not the page you'd visit, like youtube.com/watch?v=…. That code arrives with a fixed width and height, which sticks out of the page on a phone. Fix it in CSS:

iframe {
  width: 100%;
  height: auto;
  aspect-ratio: 16 / 9;
}

    Security concerns
    
    
    An iframe runs someone else's code inside your page, and that cuts both ways:
    
    
      
      
    • Clickjacking: an attacker can load a real site in an invisible iframe over a decoy button, so you click something you didn't mean to. That's why banks, social sites and many others send headers (X-Frame-Options or a Content Security Policy) telling browsers not to show them in frames. You'll see a blank box or "refused to connect". Link to them instead.
      • 
      
    • Use HTTPS: embed only https:// addresses; browsers block insecure content inside a secure page anyway.
      • 
      
    • Only embed what you need, and add sandbox to content you don't fully trust. An empty sandbox blocks scripts, forms, pop-ups and more; you then allow just what's needed, like sandbox="allow-scripts".

    The <embed> and <object> elements
    
  
    
    
    <embed> and <object> are older general-purpose elements for embedding external content, once used for plugins like Flash. With plugins gone, you'll rarely need them: <img>, <video>, <audio> and <iframe> cover nearly everything.

    Embedding PDFs
    
  
    
    
    To show a PDF preview in a page, an <iframe src="trail-map.pdf"> works in most desktop browsers. Phones often won't display it, though, so always include an ordinary link to download it, and consider whether the content would be better as an HTML page.

    Key ideas
    
      
      
        
    • SVG is shapes described in code, so it stays sharp at any size. Use it for logos, icons and diagrams.
      • 
        
    • <img> is the simplest way to add an SVG file; inline <svg> lets CSS and JavaScript reach inside.
      • 
        
    • Give every iframe a title that says what's in it. Screen readers announce it so people can decide whether to go in.
      • 
        
    • To make an embed responsive, set width: 100%, height: auto and an aspect-ratio that matches the content, like 16 / 9 for video.
      • 
        
    • loading="lazy" waits until the visitor scrolls near the embed. A YouTube player downloads close to 1 MB before anyone presses play.
      • 
        
    • Each embed is a full web page with its own scripts and tracking. Use them where they add real value.
      • 
      
    
    
    
    
    
      
    Common mistakes
    
      
      
        
    • Pasting the code with width="560" and never testing on a phone, so the video sticks out of the page.
      • 
        
    • Pasting the page address (youtube.com/watch?v=…) as the src. It must be the embed address (youtube.com/embed/…).
      • 
        
    • Trying to style what's inside the iframe with your own CSS.
      • 
        
    • Saving a photo as SVG, or an SVG icon as a large PNG.
      • 
        
    • Inline SVG with no <title> or label, so screen readers can't describe it.
      • 
        
    • Embedding a video you could simply host yourself with <video>, or vice versa: uploading a huge video file to GitHub Pages instead of YouTube.
