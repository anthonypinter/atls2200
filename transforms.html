Transforms Playground

Changing how a box looks, not where it sits

A transform changes how an element is drawn after the page has been laid out. You can slide it, turn it, grow it or slant it:

.badge {
  transform: translateY(-4px) rotate(-3deg) scale(1.1);
}

The four kinds of function are translate() (move), rotate() (turn, in deg), scale() (resize, where 1 is normal size) and skew() (slant). Each has X and Y versions, like translateX().

The key idea is that transforms don't affect layout. The browser keeps the element's original space reserved, so nothing around it moves. That's what makes transforms perfect for hover effects: a card can lift up 4px without pushing the rest of the page down. It's also why you shouldn't build layouts with them. A translated box leaves a gap where it was and overlaps whatever it lands on.

You can list several functions in one transform, separated by spaces, and order matters: each function works in the direction left by the ones before it. Rotate and then translate, and the element moves along its new, tilted direction.

transform-origin sets the point the element turns and scales around. The default is the center; transform-origin: top left makes it pivot from the corner, like a door on a hinge.

Watch out

A second transform replaces the first one completely. If a card has rotate(-2deg) and its hover state sets scale(1.05), the rotation disappears on hover. Repeat both: rotate(-2deg) scale(1.05).

Order matters
Same functions, different order
Transform functions run from right to left, and each one changes the direction the next one uses. Rotate first and "move right" points somewhere else.

  

    
transform: translateX(140px) rotate(45deg);
A
Turn in place, then slide 140px right along the page.

    
transform: rotate(45deg) translateX(140px);
B
Turn first, so "right" is now tilted 45° downward, and it slides along that tilted line.

  

  

  
In real sites
Four everyday uses

  

    
Center anything
centered
.badge {
  position: absolute;
  top: 50%; left: 50%;
  transform: translate(-50%, -50%);
}
top/left: 50% puts the corner in the middle. The translate pulls it back by half its own size.

    
Lift on hover
Hover or Tab to me
.card { transition: transform 0.2s; }
.card:hover {
  transform: translateY(-6px);
}

    
Turn an arrow
Trail conditions
Icy above 7,000 feet.
details[open] summary::before {
  transform: rotate(90deg);
}

    
Mirror an icon
➜➜
.icon-back {
  transform: scaleX(-1);
}
One arrow icon serves as both "next" and "back."

Key ideas

      
    
        
  • Transforms don't affect layout. Neighbors stay where they were, which is why they're perfect for hover effects and animation.
    • 
        
  • List several functions in one transform, separated by spaces. A second transform declaration replaces the first entirely.
    • 
        
  • transform-origin is the pin the element spins and scales around. The default is the center.
    • 
        
  • translate percentages are a percentage of the element's own size, not its parent's.
    • 
        
  • Transforms are smooth to animate. See Transitions & Animations.
    • 
      

    

    

      
Common mistakes

      
    
        
  • Writing transform: rotate(10deg); and later transform: scale(1.1); on hover, and losing the rotation. Repeat both: rotate(10deg) scale(1.1).
    • 
        
  • Transforming an inline element like a span. It's ignored: make it inline-block.
    • 
        
  • Forgetting the unit: rotate(45) does nothing. Write 45deg.
    • 
        
  • Using translate to build a layout. The original space stays reserved, so you get gaps and overlaps.
