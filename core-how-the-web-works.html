Clients and servers

Every computer on the web plays one of two roles. A client is the device you browse on, and the browser running on it. A server is a computer somewhere else that stores websites and sends out their files when asked.

ClientYour laptop or phone, running a browser
request →← response
ServerStores the site's files and sends copies on request

The client always starts the conversation by sending a request. The server answers with a response: the file, or a message explaining why it can't send it. A server never sends you anything you didn't ask for.

The other parts of the toolbox

A client and a server need more than each other. Picture the client as your house and the server as a shop:

  • Your internet connection is the street between them.
  • TCP/IP are the rules for how data travels along that street, like the rules for how a delivery is packed and addressed.
  • DNS is the address book. You know the shop's name; DNS finds its street address.
  • HTTP is the language the client and server use to talk: "Can I have this file?" "Here it is."
  • Component files are what the shop sells: code files (HTML, CSS, JavaScript) and assets (images, fonts, video).

    DNS explained

    Computers find each other by IP address, a string of numbers like 185.199.108.153. Nobody wants to remember those, so websites also get a domain name, like github.io. The Domain Name System (DNS) is a worldwide set of servers that look up which IP address goes with which domain name. Your browser asks DNS first, every time it meets a domain it doesn't already know.

    Read

    Packets explained

    Files don't travel in one piece. They're split into thousands of small chunks called packets. Each packet can take a different route, and the browser puts them back together when they arrive. If one gets lost, only that small piece is sent again, and many people can download the same site at once without waiting in line.

    HTTP basics

    HTTP (HyperText Transfer Protocol) is the set of rules for requests and responses. Every response starts with an HTTP status code, a three-digit number that says how the request went. You'll meet these all the time:

    CodeMeansYou'll see it when
    200OKThe file was found and sent. You never notice it.
    301Moved permanentlyThe page has a new address; the browser follows it automatically.
    404Not foundNothing exists at that path: a typo, or a capital letter in the wrong place.
    500Server errorSomething broke on the server's side, not yours.

    Today almost every site uses HTTPS, the same rules sent over an encrypted connection, so nobody in between can read or change what's sent.

    Dealing with files

    When you build a site, you build that folder of files yourself. Keep everything for one site in one project folder, with the home page, index.html, at the top. When someone visits the folder without naming a file, the server sends index.html.

    What structure should a website have?

    trail-club/
├── index.html
├── about.html
├── images/
│   └── mesa-trail.jpg
├── styles/
│   └── style.css
└── scripts/
    └── main.js

    File names

    Your laptop may forgive sloppy names; servers don't. Most servers treat Mesa.jpg and mesa.jpg as two different files, and spaces in names turn into %20 in addresses. So name every file and folder in lowercase, use hyphens instead of spaces, and stick to letters, numbers and hyphens.

    File paths

    To use one file from another, you write its path: images/mesa-trail.jpg from index.html, for example. You'll learn every kind of path in Creating Links.

    Tip

    Set your computer to always show file extensions. A file that looks like photo.jpg may really be photo.jpg.png, and the path won't match.

      Practice

      Build a full URL

      A short path only works inside your own site. To link to another site, you need every part of the address.

      Practice

      Fix the file names

      The files were renamed to follow the rules. Update the page so its paths match.

      Key ideas

      • The client (your browser) sends requests; the server sends responses.
      • DNS turns a domain name into an IP address before anything else happens.
      • HTTP carries requests and responses. Every response has a status code: 200 OK, 404 Not found.
      • A page is many files. The browser asks for each one separately.
      • A URL is protocol, domain, path, and sometimes a query and a fragment.
      • Name files in lowercase with hyphens, and keep one site in one folder with index.html at the top.

      Common mistakes

      • A capital letter in a file name that the code spells in lowercase. It works on your laptop and 404s on the server.
      • Spaces in file names.
      • Naming the home page Home.html or index.htm instead of index.html.
      • Linking to another site without https://, so the browser treats the domain as a file in your folder.
