How CSS Is Applied

A CSS rule picks some elements and gives them styles. Learn the names for each part of a rule, then see the three places CSS can live and which one wins when they disagree.

Rules, and where they live

HTML says what things are. CSS says how they look. A stylesheet is a list of rules, and every rule has the same shape:

h1 {
  color: #0b6b5e;
  font-size: 2rem;
}

The selector, h1, picks which elements the rule applies to. Inside the braces are declarations, each a property and a value separated by a colon and ending with a semicolon. This rule says: make every h1 teal and twice the normal text size.

CSS can live in three places:

  • An external stylesheet, a separate .css file linked from the head with <link rel="stylesheet" href="style.css">. One file can style every page of a site, so changing a color once changes it everywhere.
  • A <style> element in the head, which styles only that one page.
  • An inline style, a style="" attribute on a single element. It's handy for quick tests, but it's hard to find later and it beats your stylesheet, which makes it hard to override.

For real projects, use an external stylesheet. When the same element gets styles from more than one place, the browser has rules for deciding which wins, which you'll explore in the playground and in Cascade & Inheritance.

Tip

If none of your styles show up, the stylesheet probably didn't load. Open DevTools, check the Network tab for a red style.css, and compare the href with the file's real name and folder.

Key ideas

  • Use an external stylesheet for real projects. One file can style every page of the site.
  • Each declaration ends with a semicolon. The last one technically doesn't need it, but always add it.
  • Comments look like /* like this */. Use them to label sections of your stylesheet.
  • CSS ignores extra spaces and line breaks, so format rules one declaration per line for readability.

Common mistakes

  • A <link> with the wrong path, so no styles load at all. Check the Network tab in DevTools.
  • Writing CSS inside the <body> without a <style> tag, so it shows up as text on the page.
  • Using inline style="" everywhere, which is hard to change and beats your stylesheet.
  • HTML-style comments (<!-- -->) inside a CSS file.
