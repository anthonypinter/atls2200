Basic HTML Syntax

Every web page is written in the same small grammar: elements made of tags, attributes that add details, and a document that wraps it all up. Learn the parts, see how the browser reads them, and write a page of your own.

You'll be able to

  • Name the parts of an element: opening tag, content, closing tag and attributes.
  • Nest elements correctly, and spot void elements that never close.
  • Write attributes with the right quotes, including boolean attributes.
  • Set up a complete HTML document and explain what each part is for.
  • Show special characters with character references, and leave notes in comments.

What is HTML?

HTML (HyperText Markup Language) isn't a programming language. It's a markup language: you wrap pieces of content in labels that tell the browser what each piece is. Take this line of text:

The Mesa Trail is 6.7 miles long.

On its own it's just text. Wrap it in a paragraph element and the browser knows it's a paragraph:

<p>The Mesa Trail is 6.7 miles long.</p>

HTML lives in plain text files that end in .html. A site's home page is usually called index.html, because that's the file a server sends when someone visits a folder without naming a file.

Tip

Browsers don't care about capital letters in tag names, so <P> and <p> mean the same thing. Write them in lowercase anyway: it's what everyone else does, and it's easier to read.

Anatomy of an HTML element

Most elements have three parts. The opening tag is the element's name between angle brackets. Then comes the content. The closing tag repeats the name with a forward slash in front of it:

<p>Pack water and a map.</p>

Forgetting the closing tag is the most common beginner mistake. Sometimes the page still looks fine, because the browser guesses where the element should end. Often it guesses wrong, and the rest of the page ends up bold, or a link swallows three paragraphs.

Nesting elements

Elements can go inside other elements. This is called nesting. To stress the word very in a paragraph, put a <strong> element inside the <p>:

<p>The last mile is <strong>very</strong> steep.</p>

Think of nested elements as boxes inside boxes. You close the inner box before the outer one, so the tags close in reverse order. <p><strong>…</p></strong> overlaps, and the browser has to repair it.

Void elements

A few elements can't hold any content, so they have no closing tag. These are void elements. A line break is one: <br>. So are <img>, <input>, <meta>, <link> and <hr>. You may see them written with a slash, as in <br />. The slash is allowed but does nothing.

    Attributes

    Attributes add information about an element that you don't want to show as content. They always go in the opening tag. A class attribute, for example, gives the element a name you can target with CSS:

    <p class="trail-note">Closed after heavy rain.</p>

    Every attribute follows the same pattern: a space after the element name (or the previous attribute), the attribute's name, an equals sign, and the value in quotes.

    Adding attributes to an element

    Some elements need attributes to work at all. An image needs src to say which file to show. It should also have alt, the alt text read aloud by screen readers and shown if the image fails to load. width and height let the browser save the right amount of space before the image arrives:

    <img src="royal-arch.jpg" alt="Sandstone arch above a pine forest" width="400" height="300">

    Boolean attributes

    Some attributes are simply on or off. Writing the name turns them on; leaving it out turns them off. disabled is one: it greys out a form control so nobody can use it.

    <input type="text" disabled>

    You might see disabled="disabled" or even disabled="false". Both still turn it on. Only leaving the attribute out turns it off.

    Omitting quotes around attribute values

    A value with no spaces works without quotes, like href=trails.html. But as soon as a value has a space, the browser thinks the value has ended and treats each extra word as a new attribute. That's why you should always use quotes.

    Single or double quotes?

    Single and double quotes both work. Pick one style and stick with it. Just don't mix them in one value, like title="Mesa Trail'. To put a quote inside a value, wrap the value in the other kind of quote, or write the quote as &quot;.

    Anatomy of an HTML document

    Elements on their own aren't a web page yet. A full page wraps them in a few standard pieces that every HTML file starts with:

    <!doctype html>
<html lang="en-US">
  <head>
    <meta charset="utf-8">
    <title>Boulder Trails</title>
  </head>
  <body>
    <p>This is my page.</p>
  </body>
</html>

    The first line, the DOCTYPE, is a leftover from the early web. It used to point to a set of rules the page had to follow. Today it does one job: it tells the browser to use modern, standard behavior instead of an old compatibility mode. Write <!doctype html> and forget about it.

    Everything else sits inside the <html> element. The head holds information about the page that isn't shown on it, such as the title in the browser tab. The <body> holds everything visitors see. Click each line below to see what it does.

      Character references: special characters

      Five characters mean something to HTML itself. To show them as text, write a character reference instead. Type below to see what needs escaping.

      Write this in your HTML
      
    
      The five special characters
      
      ShowsWriteWhy
      
        
      <&lt;Would start a tag
      
        
      >&gt;Would end a tag
      
        
      "&quot;Would end a double-quoted value
      
        
      '&apos;Would end a single-quoted value

      In ordinary text only < and & really have to be escaped; quotes matter inside attribute values. Other symbols like © or é don't need references at all, as long as the page has <meta charset="utf-8">.

      HTML comments
      
  
      
    
      A comment is a note in your code that the browser ignores. Start it with <!-- and end it with -->. Use comments to explain why something is there, or to switch off a piece of the page while you test:
      
    
      <p>Open daily, sunrise to sunset.</p>
<!-- Hidden until the winter hours are confirmed:
<p>Winter hours: 7am to 5pm.</p>
-->
      
    
      Watch out
      Comments don't show on the page, but anyone can read them with View Source. Never put passwords, private notes or anything you wouldn't want public in a comment.

      • Leaving out a closing tag, so formatting leaks into everything after it.
        •
