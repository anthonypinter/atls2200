Read

CSS that depends on the screen

A media query wraps some CSS in a condition, so those rules apply only when the condition is true. Almost always, the condition is the screen's width:

.cards {
  display: grid;
  gap: 16px;
}
@media (min-width: 600px) {
  .cards { grid-template-columns: 1fr 1fr; }
}
@media (min-width: 1000px) {
  .cards { grid-template-columns: 1fr 1fr 1fr; }
}

Read min-width: 600px as "600px or wider". On a phone, neither query applies and the cards stack in one column. At 700px, the first applies: two columns. At 1200px, both apply, and since they conflict, the later one wins: three columns. That's why queries are listed from smallest to largest.

The width where a query kicks in is called a breakpoint. Don't choose breakpoints from a list of phone and tablet sizes; there are thousands of devices, and new ones every year. Instead, widen your browser window slowly, and add a breakpoint wherever your layout starts to look wrong.

This approach, a simple base layout plus min-width queries that add complexity, is called mobile first, and it's the subject of Mobile-First Workflow.

Watch out

Media queries on phones depend on the viewport meta tag in your head. Without it, the phone pretends to be a 980px-wide desktop, and your phone styles never switch on.

    Key ideas

    • Mobile first: write the phone layout with no media query, then add min-width queries as the screen gets bigger.
    • @media (min-width: 600px) means "600px or wider." Both queries are on at 1000px.
    • Later rules win when they conflict, so list queries from smallest to largest.
    • Pick breakpoints where your layout starts to look wrong, not by device names.

    Common mistakes

    • Forgetting <meta name="viewport" content="width=device-width, initial-scale=1"> in the <head>. Phones will ignore your queries without it.
    • Missing the space or parentheses: @media(min-width:600px) is fine, but @media min-width: 600px is not.
    • Putting the media query above the base rules, so the base rules override it.
    • Mixing min-width and max-width queries until nobody can tell which applies.
