Media Queries

A media query applies CSS only when a condition is true: the screen is at least this wide, the page is being printed, the device has a mouse. It's how one stylesheet adapts to every device.

You'll be able to

  • Write media queries with media types, feature rules and the newer range syntax.
  • Combine conditions with and, or (commas) and not.
  • Choose breakpoints based on your content, and build a layout mobile first.
  • Recognise when a flexible layout doesn't need a media query at all.

Media query basics

A media query wraps some CSS in a condition. The rules inside only apply while the condition is true:

@media media-type and (media-feature-rule) {
  /* CSS rules go here */
}

Media types

The media type says what kind of output the CSS is for: screen, print or all. Leave it out and the query applies to everything. A print stylesheet is a common use:

@media print {
  body { font-size: 12pt; }
  nav, .ads { display: none; }
}

Media feature rules

Features test something about the device or the window. The one you'll use most is width, with a min- or max- prefix:

@media (min-width: 600px) { … }   /* 600px or wider */
@media (max-width: 599px) { … }   /* up to 599px */

A few others are worth knowing:

  • (orientation: landscape) or portrait: is the window wider than it is tall?
  • (hover: hover): can the main input hover, like a mouse? Touchscreens can't, so hover-only menus fail there.
  • (pointer: fine) or coarse: is it precise, like a mouse, or a finger? Make targets bigger for coarse.

Using ranged syntax

Newer browsers let you write width tests as comparisons, which is easier to read than min- and max-:

@media (width >= 600px) { … }            /* same as min-width: 600px */
@media (30em <= width <= 50em) { … }     /* between 30em and 50em */

More complex media queries

"and" logic in media queries

Join conditions with and; all of them must be true:

@media screen and (width >= 600px) and (orientation: landscape) { … }

"or" logic in media queries

Separate whole queries with commas; any one being true is enough:

@media (width >= 600px), (orientation: landscape) { … }

"not" logic in media queries

not at the start reverses the whole query. not all and (orientation: landscape) matches portrait.

How to choose breakpoints

The width where a query kicks in is called a breakpoint. Don't choose breakpoints from a list of phone and tablet sizes: there are thousands of devices, and new ones every year. Instead, start narrow and widen your browser window slowly (or use the responsive design mode in your browser's DevTools). Add a breakpoint wherever your layout starts to look wrong: lines too long, cards too stretched, too much empty space.

When two queries both match and set the same property, the later one wins, just like any other rule. So list min-width queries from smallest to largest.

    Mobile-first responsive design

    There are two ways to write those queries. You can write the wide-screen layout first and use max-width queries to undo it on small screens. Or you can write the simple, single-column layout first, with no query at all, and use min-width queries to add columns as the screen grows.

    The second approach is called mobile first. It usually means less CSS, because you never write a rule just to cancel another. And because single-column, in source order, is close to what HTML does with no CSS, your base layout is mostly done before you start. The next lesson, Responsive Design and Mobile First, builds a whole page this way.

    Creating your own mobile-first design

    A mobile-first stylesheet has the same shape every time: base styles, then one query per breakpoint.

    /* Base: one column for every screen */
body { width: 90%; margin: 0 auto; }

/* Medium: two columns */
@media screen and (width >= 40em) {
  article { display: grid; grid-template-columns: 3fr 1fr; column-gap: 20px; }
  nav ul { display: flex; }
}

/* Wide: a third column */
@media screen and (width >= 70em) {
  main { display: grid; grid-template-columns: 3fr 1fr; }
}

    Notice the breakpoints are in em. If someone sets a larger default text size, an em breakpoint moves with it, so the layout switches to fewer columns when the text needs more room.

    viewport meta

    None of this works on phones without one line in your <head>:

    <meta name="viewport" content="width=device-width, initial-scale=1">

    Without it, mobile browsers pretend to be about 980px wide and shrink the whole page down, so your phone layout never switches on.

    Do you really need a media query?

    Flexbox and Grid are flexible by design, so many layouts adapt with no breakpoint at all. This grid fits as many 200px-plus columns as there's room for, from one on a phone to five on a monitor:

    .cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
  gap: 16px;
}

    Reach for a media query when something has to change at a size: the nav moves, a sidebar appears, the order of things shifts. For "more columns when there's room", let the layout do it.

    Print, hover, orientation and ranges

    Four queries that aren't about a simple minimum width.

    Key ideas

    • @media print, screen or all picks the output; features like (min-width: 600px) test the device.
    • Range syntax reads naturally: (width >= 600px), (30em <= width <= 50em).
    • and needs every condition; a comma means or; not reverses a whole query.
    • Mobile first: base styles for phones, then min-width queries, smallest to largest.
    • Pick breakpoints where your layout starts to look wrong, and don't forget the viewport meta tag.

    Common mistakes

    • Forgetting the viewport meta tag, so phones ignore your queries.
    • @media min-width: 600px without parentheses. Features always go in brackets.
    • Putting a query above the base rules, so the base rules override it.
    • Hiding important features behind :hover without checking (hover: hover).
