What is JavaScript?

HTML gives a page its structure, CSS gives it style, and JavaScript gives it behavior. Here's what JavaScript can do, how it runs in the browser, how to add it to a page, and a first look at a small program.

A high-level definition

JavaScript is a programming language that lets you make web pages do things: update content as you watch, show a map you can drag around, animate graphics, check a form before it's sent. It's the third layer of the web's layer cake:

  • HTML gives the page structure and meaning: a heading, a paragraph, a button.
  • CSS styles it: colors, fonts, layout.
  • JavaScript adds behavior: what happens when someone clicks the button.
const button = document.querySelector("button");

button.addEventListener("click", updateName);

function updateName() {
  const name = prompt("Enter a new name");
  button.textContent = `Player 1: ${name}`;
}

Each layer builds on the one before. JavaScript can't add behavior to a button that doesn't exist.

Tip

JavaScript has nothing to do with Java. The similar name was a marketing decision in 1995, and it has confused people ever since.

So what can it really do?

The core language gives you the basics of programming: store values in variables, do math and work with text, and run code when something happens (an event, like a click).

On top of that, browsers provide APIs, ready-made toolkits you can use from JavaScript:

  • The DOM API lets you change the HTML and CSS of the page, which is how pop-ups, menus and live updates work.
  • The Geolocation API finds where the user is (with permission).
  • The Canvas and WebGL APIs draw 2D and 3D graphics.
  • Audio and video APIs play and record media.

There are also third-party APIs from companies like map and payment services. This course stays with the core language and the DOM.

What is JavaScript doing on your page?

When a page loads, the browser reads the HTML, applies the CSS, and runs the JavaScript. The script can then keep changing the page while it's open.

Browser security

Each browser tab runs its code in its own separate environment. Code in one tab can't see or change another tab or another site, which stops a malicious site from reaching into your bank's tab.

JavaScript running order

The browser runs your code from top to bottom, one line at a time. So order matters: you can't use something before the line that creates it. Run this and read the error:

Interpreted versus compiled code

Some languages are compiled into a program before they run. JavaScript is interpreted: the browser takes your code as text and runs it. (Modern browsers compile it on the fly behind the scenes to make it fast, but you never have to.)

Server-side versus client-side code

JavaScript in a web page is client-side: it runs in the visitor's browser. Server-side code runs on the web server before the page is sent. JavaScript can run on servers too, with Node.js, but this course is all client-side.

Dynamic versus static code

A static page shows the same content every time. A dynamic page can change what it shows, for example by building a list from data or updating a score. JavaScript is what makes a page dynamic in the browser.

How do you add JavaScript to your page?

JavaScript goes in a <script> element.

Internal JavaScript

You can write the code inside the element, usually just before </body>, so the elements above it already exist when it runs.

External JavaScript

Usually, it's better to keep JavaScript in its own file, just as CSS has its own stylesheet, and link it from the <head>:

<script defer src="script.js"></script>

MDN's examples use type="module" instead of defer. Modules wait in the same way, but they only work when the page is served by a web server (GitHub Pages, or a local one like VS Code's Live Server), not when you double-click the file.

Inline JavaScript handlers

You'll see old code like <button onclick="createParagraph()">. Don't do this: it mixes behavior into your HTML, and you'd have to add the attribute to every button by hand.

Using addEventListener instead

Keep the behavior in your script, and attach it from there. This finds every button and gives each one the same behavior:

const buttons = document.querySelectorAll("button");

for (const button of buttons) {
  button.addEventListener("click", createParagraph);
}

Script loading strategies

The browser reads HTML from top to bottom. A plain <script src> in the head makes it stop, download and run the script before the body exists, so the script can't find the elements it needs. defer (or type="module") says: download now, but run after the whole page has been read. (async runs as soon as it's downloaded, in any order, which suits independent scripts like analytics.)

    Key ideas
    
      
      
        
    • HTML is structure, CSS is presentation, JavaScript is behavior.
      • 
        
    • Browser APIs (like the DOM) let JavaScript change the page, draw graphics and more.
      • 
        
    • Each tab runs its code separately, from top to bottom; you can't use something before it's created.
      • 
        
    • Link scripts with <script defer src="script.js">, or type="module" on a server.
      • 
        
    • Attach behavior with addEventListener, not onclick attributes.
      • 
      
    
    
    
    
    
      
    Common mistakes
    
      
      
        
    • A plain <script src> in the head with no defer: the elements don't exist yet, so you get null errors.
      • 
        
    • Writing <script src="script.js" />. A script tag always needs a closing </script>.
      • 
        
    • Expecting type="module" to work from a double-clicked file.
      • 
        
    • A wrong path in src: nothing happens, and the console shows a 404 for the file.
