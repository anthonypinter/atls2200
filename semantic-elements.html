Semantic Elements

Semantic elements describe what content is, not how it looks. They look the same as a plain div, but screen readers, search engines and other developers can tell a navigation menu from a footer.

Click a region to see what it means.

Practice

Which element fits?

Pick the best element for each piece of content.

Key ideas

  • Use <div> only when no other element describes the content. It means "a box, nothing more."
  • One <main> per page, holding the content that's unique to that page.
  • <article> makes sense on its own (a blog post, a product card). <section> is a themed part of something bigger and usually has a heading.
  • Semantic elements don't change how things look. You still style them with CSS.

Common mistakes

  • Choosing an element for its default look, like <h3> because the text is small. Style the size with CSS instead.
  • Making a clickable <div> instead of a <button>. Keyboards and screen readers can't use it.
  • Wrapping every group of links in <nav>. Save it for major navigation.
  • Skipping heading levels (h1 to h4) to get a smaller font.
