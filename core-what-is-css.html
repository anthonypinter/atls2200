What is CSS?

HTML says what each part of a page is. CSS (Cascading Style Sheets) says how it looks: colours, fonts, spacing, layout, even animation. This lesson covers how a rule is written and the three places it can live.

You'll be able to

  • Explain what browsers do with an unstyled page, and what CSS is for.
  • Name the parts of a CSS rule: selector, declaration, property and value.
  • Add CSS with an external stylesheet, a <style> element or an inline style, and know which to use.
  • Recognise functions, @rules, shorthand properties and comments.

Browser default styles

Even a page with no CSS at all isn't plain text. Headings are big and bold, lists have bullets, links are blue and underlined. That's because every browser has a built-in default stylesheet that makes unstyled HTML readable.

Those defaults are deliberately plain, and they differ slightly between browsers. Your CSS builds on top of them.

What is CSS for?

CSS controls everything about how a page looks:

  • Text: fonts, sizes, colours, spacing between lines and letters.
  • Boxes: backgrounds, borders, rounded corners, shadows and the space around everything.
  • Layout: columns, grids, sidebars, and how all of it rearranges on a phone.
  • Movement: transitions and animations.

This week covers the language itself. Weeks 4 to 6 use it for styling, layout and responsive design.

CSS syntax basics

A stylesheet is a list of rules, and every rule has the same shape:

h1 {
  color: navy;
  font-size: 2rem;
}

The selector, h1, picks which elements the rule applies to. Inside the braces are declarations, each a property and a value separated by a colon and ending with a semicolon. This rule says: make every h1 navy and twice the normal text size.

How is CSS applied to HTML?

When a browser loads a page, it reads the HTML into a tree of elements (the DOM), reads the CSS, and works out which rules apply to which elements. Then it lays out and paints the result. Every element can be matched by many rules at once, and each rule can match many elements.

So one rule, p { color: navy; }, colours every paragraph on the page, and adding a paragraph later means it's styled automatically. Try it.

Adding CSS to our document

CSS can live in three places:

External stylesheets

A separate .css file, linked from the <head>:

<link rel="stylesheet" href="styles.css">

The href is a path, just like a link's: css/styles.css if it's in a folder, ../styles.css from a page one folder down. One file can style every page of a site, so changing a colour once changes it everywhere, and browsers download it only once. Use this for real projects.

Internal stylesheets

A <style> element in the head. It styles only that one page, so a multi-page site would repeat it in every file.

Inline styles

A style attribute on a single element: <span style="color: purple">. It mixes styling into your content, is hard to find later, and beats your stylesheet, which makes it hard to override. Avoid it.

Using common selectors

Next lesson covers selectors in depth. Here's a quick tour of the ones you'll use most:

  • Elements: p { } styles every paragraph. List several with commas: p, li { }.
  • Classes: add class="special" in the HTML, then select it with a dot: .special { }.
  • Location: li em { } selects ems inside list items; h1 + p { } selects a paragraph straight after an h1.
  • State: a:hover { } styles a link while the pointer is over it; a:visited { } once it's been visited.

Other CSS syntax features

Functions

Some values are calculated by a function, written as a name and brackets: width: calc(90% - 30px); or transform: rotate(0.8turn);.

@rules

Rules starting with @ give CSS special instructions. The most common, @media, applies styles only when a condition is true, like a wide enough screen (Week 6):

@media (width >= 30em) {
  body { background-color: lightblue; }
}

Shorthand properties

Some properties set several others at once. padding: 10px 15px 15px 5px; sets the top, right, bottom and left padding, going clockwise from the top.

    Comments

    Comments are notes the browser ignores, written between /* and */. Use them to label sections of a stylesheet, or to switch a rule off while you test.

    /* Trail cards */
.card { padding: 1rem; }

    White space

    CSS ignores extra spaces and line breaks between parts, so put one declaration per line for readability. But spaces inside a property name or between a number and its unit break it: margin: 0auto; and padding- left: 10px; are both invalid.

    Key ideas

    • Browsers have default styles; your CSS builds on them.
    • A rule is a selector plus a declaration block; each declaration is property: value;.
    • Use an external stylesheet for real projects. One file can style every page of the site.
    • Shorthands like padding go clockwise: top, right, bottom, left.
    • Comments look like /* like this */.

    Common mistakes

    • A <link> with the wrong path, so no styles load at all.
    • A missing semicolon, colon or brace, which breaks the next declaration or rule.
    • Using inline style="" everywhere: hard to change, and it beats your stylesheet.
    • HTML comments (<!-- -->) or // in a CSS file.
    • A space between a number and its unit: 16 px.
