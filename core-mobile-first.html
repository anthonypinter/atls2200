Responsive Design and Mobile First

Responsive design is the idea that one page should work on every screen, by adapting its layout instead of serving a separate mobile site. Mobile first is the way to build it: start with the phone, and add to it as the screen grows.

You'll be able to

  • Explain what makes a design responsive: fluid layouts, flexible media and media queries.
  • Use flexbox and grid to build layouts that adapt.
  • Explain why the viewport meta tag is needed.
  • Build a page mobile first, adding min-width queries for wider screens.

Precursor to responsive design: mobile web design

When phones first got web browsers, many companies built a second, separate mobile site (often at an address like m.example.com) and used code on the server to guess which device was asking. Two sites meant twice the work, and the guessing often went wrong: tablets got the phone site, new phones got the desktop one.

Phones are still different from laptops in ways that matter, like slower connections and battery life. But the answer today is one site that adapts.

Introducing responsive web design

The term responsive web design was coined by Ethan Marcotte in 2010. It combines three ideas:

  • Fluid layouts: columns sized in percentages or fr, not fixed pixels, so they stretch and shrink with the window.
  • Flexible media: images and video that shrink to fit, with max-width: 100%.
  • Media queries: rules that change the layout at certain widths.

Here's a useful fact: HTML is responsive by default. Text wraps, blocks fill the width they're given. Most responsive problems come from CSS that fixes a size, like a width: 960px wrapper from the days when every screen was a desktop.

Media Queries

You met media queries in the last lesson. In responsive design, each one marks a breakpoint where the layout changes, for example from one column to two:

@media screen and (width >= 80rem) {
  .container { margin: 1em 2em; }
}

Use relative units like em or rem for breakpoints where you can, and remember that a flexible layout may not need many queries at all.

Responsive layout technologies

Modern layout tools are flexible by design, which is half the work of responsive design.

Flexbox

Flex items grow and shrink to share the space: flex: 1 and flex: 2 make the second column twice the width of the first at any window size.

@media (width >= 600px) {
  .wrapper { display: flex; }
  .col1 { flex: 1; margin-right: 5%; }
  .col2 { flex: 2; }
}

CSS grid

The fr unit does the same in a grid:

@media (width >= 600px) {
  .wrapper {
    display: grid;
    grid-template-columns: 1fr 2fr;
    column-gap: 5%;
  }
}

Responsive images/media

  


Images, video and other embeds have a fixed size, so they need one rule to make them fluid:

    
img, picture, video {
  max-width: 100%;
  height: auto;
}

    
That stops them overflowing, but a phone still downloads the big file. HTML has tools for sending a smaller file or a different crop, which are the subject of Responsive Images. And where you can, use CSS gradients and shadows instead of image files: they're tiny and sharp at any size.

Responsive typography

  


Text should change size too: a heading that looks right on a laptop may be too big for a phone. You can step the size up with media queries:

    
h1 { font-size: 2rem; }
@media (width >= 1200px) {
  h1 { font-size: 4rem; }
}

    
Or make it grow smoothly with the window by mixing in viewport units, as in font-size: calc(1.5rem + 4vw). Never use vw on its own for text: it doesn't grow when people zoom in. Fluid Sizing covers this, and clamp(), in detail.

The viewport meta tag

  


Every responsive page needs this line in its <head>:

    
<meta name="viewport" content="width=device-width, initial-scale=1">

    
When phones first got browsers, most sites were built for desktop widths. So mobile browsers pretend the screen is about 980px wide, lay the page out at that size, then shrink the whole thing to fit. That kept old sites readable, sort of. But it also means your phone layout never switches on, because the browser says it's 980px wide. The viewport meta tag says "this page is built for real device widths", so the browser uses the phone's actual width.

Building mobile first

  


Now put it together. There are two ways to make a site responsive. You can design for a laptop and then squeeze it onto a phone, undoing styles as the screen shrinks. Or you can start with the phone and add to it as the screen grows. The second way is mobile first, and it almost always means less CSS and fewer bugs.

    
The phone layout is usually the simplest: one column, everything stacked, full width. So your base styles, outside any media query, describe the phone version, and each min-width query adds only what changes on wider screens. You never write a rule just to undo another one.

    
Mobile first also applies to content. If something is too much for a phone, ask whether it's needed at all, rather than hiding it on small screens.

    
Tip
Narrowing your browser window is a good first check, but test on a real phone too. Touch targets, real font sizes and the on-screen keyboard only show up on the real thing.

    Common mistakes
    
      
      
        
    • Designing for a laptop, then cramming it onto a phone with lots of max-width overrides.
      • 
        
    • Fixed widths like width: 960px on a wrapper, which cause sideways scrolling on phones.
      • 
        
    • Forgetting the viewport meta tag.
      • 
        
    • Hiding important content on mobile instead of rearranging it.
